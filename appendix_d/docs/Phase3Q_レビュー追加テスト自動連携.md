# Phase 3Q レビュー追加テスト自動連携

Phase 3Pの対応タスクのうち `RETEST` を、既存の比較キャンペーンへ安全に接続する。担当者は分析実行画面で対応タスクと検証データセットを選び、元レビューの比較と同じモデル集合・評価方法で追加テストを開始できる。

## 操作

1. `/ui/analysis` の「レビュー後の対応を管理する」で、種類が「追加テスト」の対応タスクを登録する。
2. 「追加テストを実行」で未着手または保留中の対応と、検証するデータセットを選ぶ。
3. 「追加テストを開始」を押す。対応状態は追記履歴によって「対応中」になる。
4. 既存の適合試験・予測・自動比較Workerが処理する。画面は比較キャンペーンの実行中状態を自動更新する。
5. 比較成功時は対応を「完了」にし、キャンペーンIDと比較IDを完了根拠へ記録する。失敗時は安全な理由を付けて「保留」に戻し、修正後に再実行できる。

## APIと認可

- `POST /api/model-drift-review-actions/{action_id}/retests`: 追加テストを登録する。`ANALYZE` 権限。
- `GET /api/model-drift-review-retests`: 追加テストと結果リンクを参照する。`READ` 権限。

開始要求はrequest keyで冪等化する。同じ利用者・request keyの再送は同じ比較キャンペーンを返し、異なるデータセットへの使い回しを拒否する。画面の期待revisionが古い場合も409で拒否する。

## 保存と自動同期

`model_review_retests` は対応タスク、元キャンペーン、対象snapshot、新キャンペーン、要求者を不変に結び付ける。比較キャンペーン自動完了Workerは未同期リンクを定期確認し、比較結果の作成成功または安全化した失敗理由を、リンク結果と対応イベントへ同一transactionで保存する。Workerが結果保存直後に停止しても次回pollで再同期でき、同じ結果イベントは重複しない。

追加テストは元キャンペーンのモデル集合、主評価期間またはhorizon、評価policyを再利用する。実験のProvider既定値や適合試験、run、比較結果は既存台帳を通じて新しい識別子で記録する。レビュー判断、採用、昇格、rollbackは自動変更しない。
