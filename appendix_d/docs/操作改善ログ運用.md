# 操作改善ログ運用

## 目的

担当者画面の利用状況を、開発チームが画面改善へ使える構造化データとして蓄積する。API監査ログは通信の成否を確認するために継続し、操作改善ログは「どの手順で迷ったか」「完了まで何秒かかったか」「どの失敗が多いか」を確認するために使用する。

## 収集する情報

- 画面と手順番号
- 接続、入力方法の変更、データ選択、分析開始、受付、失敗
- ページ表示から各操作までの所要時間
- 保存・内容確認、列設定判定、分析受付ごとの処理時間
- アップロードまたは指定フォルダーの区分
- CSVまたはZIPの区分
- ファイル容量、列数、候補件数、ファイル更新日の区分
- 選び直し回数、再試行回数、指定フォルダー一覧の更新成否
- 画面幅の区分
- オンラインまたはオフラインの区分
- 自動mapping照合の成否
- HTTP statusまたは固定分類による失敗種別
- 認証済み担当者、操作session、操作順序、受信時刻
- 分析jobまたはbatchの受付ID。画面上の失敗とbackendの処理記録を照合するために使う

## 収集しない情報

- ファイル名と保存path
- CSV・ZIPの内容、列値、商品名、JAN、数量
- 接続コード、Authorization header
- 自由入力、検索語、ブラウザー履歴
- 端末固有ID、IP address、詳細なUser-Agent

`POST /api/operation-events`はmetadata keyを固定allowlistで検査する。未定義key、長い文字列、入れ子の値を拒否するため、画面の誤実装で原本情報を保存できない。

## 保存と権限

操作記録は既存PostgreSQLの`operation_events`へ追記する。同じ`event_id`の再送は同じ記録へ収束し、内容の変更を拒否する。

- 記録: 認証済み利用者
- 一覧・集計: `APPROVE`権限
- CSV出力: `EXPORT`権限
- 初期保持期間: 180日
- 設定: `KIBAN_OPERATION_EVENT_RETENTION_DAYS=180`

保持期間は1〜3650日で設定する。API processは1時間に最大1回、保持期間を超えた記録を削除する。

## 開発へのフィードバック

`/ui/feedback`で期間を選択し、次を確認する。

1. 接続から分析受付までの手順別到達数
2. データ選択後に分析を開始しなかったsession数
3. mapping不足、API失敗、予期しない失敗の件数
4. 分析開始までの中央値と90 percentile
5. アップロードと指定フォルダーの利用比率
6. 接続後、データ選択後、分析実行後のどこで止まったか
7. 保存・内容確認、列設定判定、分析受付の中央値と遅い10%の時間
8. 選び直しや指定フォルダー更新が多いか

画面は集計値から改善候補を表示する。改善候補は自動決定ではなく、担当者への聞き取りや実画面確認を始めるための目印として使用する。

| 観測した状態 | 確認する内容 | 改善例 |
|---|---|---|
| 接続後にデータを選ばない | 選択方法が見つかるか | 初期説明、ボタン名、配置を変更 |
| 選択後に分析を押さない | 準備完了が伝わるか | 次の操作を強調、不要な表示を削減 |
| 選び直しが多い | 対象ファイルを判別できるか | 更新日時、用途、最新候補を明示 |
| mapping不足が多い | 新しい列形式か | mapping候補の追加、列名ガイドを表示 |
| 内容確認が遅い | ファイル容量や通信の影響か | 進捗表示、ZIP処理・読込処理を改善 |
| 分析受付が遅い | API・DB・worker待ちか | 待機表示、キューとDB処理を確認 |

詳細分析が必要な場合はCSVを出力する。CSVはアクセス制限された社内保管場所で扱い、担当者IDを含むため外部へ公開しない。

## 改善サイクル

月1回または利用試験の終了時に、到達率と失敗上位を確認する。改善対象、対応内容、公開日をissueへ記録し、公開後は同じ指標の変化を確認する。個別担当者の評価には使用せず、画面と手順の改善に限定する。

## STEP 2〜4で追加する計測

内容確認、予測実行、結果表示の担当者画面を追加する際は、次の構造化イベントを同じsessionへ記録する。

- 内容確認を開いた、警告を確認した、戻ってデータを選び直した
- 予測開始、queue待ち、実行開始、完了、失敗
- 結果画面を開いた、比較を切り替えた、CSVを出力した
- 結果を採用候補にした、再実行した、操作を終了した
- 任意の1click回答「分かりやすい」「迷った」「処理が遅い」「結果の見方が不明」

自由記述は原本情報が混入しやすいため、初期運用では収集しない。必要になった場合は操作ログとは別の権限・保持期間・確認手順を設ける。
