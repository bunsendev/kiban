# Phase 3T Windows Portable Pilot評価Gate

## 目的

Pilot Scopeで実際に使った候補版をBaselineと同じ後日実績で比較し、担当者が次の対応を判断するためのGateである。機械判定は判断材料に限定し、正式採用、設定変更、Pilot停止、rollbackを自動実行しない。

## 前提

- Pilot適用計画が`PILOT_ACTIVE`で、元の正式変更案の承認が現在も有効である。
- 手順12-2のRuntime週次評価に、候補版の集計とBaselineとの比較が各1件ある。
- 候補版のRuntime証跡に記録されたPilot Scopeが、適用計画の範囲内である。
- 比較対象は同じ業務日・JAN・倉庫で、Actualの取込元版、SHA-256、数量が一致するcaseだけである。

## 版付き評価基準

画面の手順15-3で、評価基準版と次の閾値を入力する。

- 最小観測日数、最小共通Actual件数
- Runtime未特定率の上限
- 候補版からBaselineを引いたMAEとWAPEの上限
- 担当者修正率の上限
- 同じActual集合における欠品、期限切れ、倉庫間移動数量の上限

欠品等は、全共通Actualで値が取得できた場合だけ合格とする。空欄を0に変換しない。観測日数または件数だけが不足する場合は「観測を継続」、それ以外の基準違反は「Baselineへ戻す作業を依頼」を推奨する。全条件を満たした場合だけ「正式採用の受入審査へ送る」を選択できる。

## 操作

1. 手順12-2でRuntime週次評価を固定する。
2. 手順15-3で`PILOT_ACTIVE`の適用計画とRuntime週次評価を選ぶ。
3. 評価基準版と閾値を確認し、［Pilot評価Gateを固定］を押す。
4. 合否、実績値、基準値を確認する。
5. 「観測を継続」「Pilotを停止」「Baselineへ戻す作業を依頼」「正式採用の受入審査へ送る」のいずれかと理由を追記する。
6. 手順15-4で、停止確認、受入基準、または復旧検査を全件確認し、評価証跡と一緒に適用履歴へ保存する。

評価後の引渡し条件と操作は[Pilot完了Gate](Phase3T_Portable_Pilot完了Gate.md)を参照する。

## 保存と監査

評価は`Data/State/PilotEvaluationGates`、担当者判断は`Data/State/PilotEvaluationDecisions`へ保存する。評価は適用計画、最新の開始Gateイベント、Runtime週次評価、基準版と閾値をSHA-256で固定する。判断はrevisionと直前レコードのSHA-256を持つ追記型で、再起動後も同じ内容を再検証する。現場PCの長いパス制限に備え、判断ファイル名には評価hashの短縮接頭辞を使うが、ファイル内容には完全な評価IDを保持する。

## 制約

人工データでの合格は実データの精度や業務効果を保証しない。正式採用には現場で十分な観測期間と共通Actualを蓄積し、担当者が評価根拠を確認する必要がある。

`PAUSE_PILOT`を選んだ後も、手順15-4で担当者が明示確認するまで候補版の選択状態は変わらない。確定後の動作は[Pilot停止Gate](Phase3T_Portable_Pilot停止Gate.md)に定める。
