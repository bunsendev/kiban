# Phase 2X 採用済み在庫の時点安全な特徴ビュー

## 目的

Phase 2Wで正式採用した在庫正規化結果を、JAN有効期間に従ってcanonical商品へ接続し、後続分析が参照できる再現可能な読み取りビューを提供する。在庫を予測モデルへ自動投入せず、採用時刻と名寄せ版を明示して将来情報の混入を防ぐ。

## 時点制約

利用者はtimezone付き`as_of`と`mapping_version`を指定する。システムは`as_of`以前で最新のAPPROVED判断だけを選び、その判断時刻を全在庫値の`available_at`とする。採用前の時点から在庫値を参照することはできない。

在庫日のJANについて、指定した名寄せ版の有効期間が一致するcanonical商品を解決する。未対応が1件でもある、または有効期間が競合する場合は`BLOCKED`とし、後続用の行や数量合計を返さない。診断は件数だけを返し、未対応JANをAPIや画面へ出さない。

## 再現性

特徴ビューIDは次の不変条件をcanonical JSON化してSHA-256で作る。

- 採用判断ID
- 在庫正規化ジョブID
- JAN名寄せ版
- UTCへ正規化した参照時点

元の在庫結果、採用判断、JAN名寄せはすべて追記型であるため、同じ条件から同じビューIDと結果を再現できる。

## APIと画面

`POST /api/inventory-feature-views`はREAD権限で利用し、件数、接続判定、利用可能時刻、特徴ビューID、ページングしたcanonical商品・拠点・日付・単位・在庫数量を返す。

`/ui/intake`の在庫正規化履歴からJAN名寄せ版と参照時点を指定し、解決件数、未対応件数、期間競合件数、利用可能時刻を確認できる。

## 対象範囲

このビューは後続処理との安全な境界であり、現行の出荷予測datasetや既存モデルの特徴量を変更しない。在庫を特徴量として採用するには、起点別の利用可能性、欠測の意味、効果比較を別途受入する必要がある。在庫配置最適化や自動発注は実装仕様上の後続開発である。
