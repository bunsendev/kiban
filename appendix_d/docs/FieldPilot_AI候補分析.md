# Field Pilot: ローカルAIによる投入ファイルの候補分析

## 対象範囲

未知のCSVを投入して「投入したファイルを確認」した後、新しい形式の確認欄で
「AIに分類候補を聞く」を押すと、ローカルのOllamaへ列名・列の値型だけを渡す。
AIはファイル種別、列の役割、数量単位の候補を返す。原本行・商品名・数量値・JAN値は送らない。
モデルが返した列名は元のヘッダーに存在するものだけ採用する。提案は画面表示のみで、
構造の承認、JAN確定、単位換算、正式取込、予測可否を変更しない。

既存ルールによる分析・確認は常に利用できる。モデル未設定時はボタンを表示しない。
モデルの停止・応答異常時は通常の確認に戻る。CSV以外、PDF解析、商品別JAN候補のAI順位付け、
換算値提案、確定結果に基づく予測更新は後続段階の対象である。

## ローカル設定

Ollamaを現場PCにインストールしてモデルを用意し、Field Pilotの起動環境に
`KIBAN_FIELD_PILOT_AI_MODEL=<インストール済みモデル名>` を指定する。
通信先は `127.0.0.1:11434` に固定している。外部サーバーには接続しない。
モデル名が未設定ならAI機能は無効のまま起動する。モデルの選定、ライセンス、
PCのメモリ・応答時間は導入PCで別途確認する。モデル本体を配布ZIPへ含めない。

Ollamaの `POST /api/generate` で `stream: false` と JSON Schema形式の `format` を使う。
接続はプロキシを経由せず、応答は20秒で打ち切り、16 KiBを超える応答は破棄する。
モデル出力を原本や命令として実行しない。

## 現場での確認

1. 未知のCSVを投入し、「投入したファイルを確認」を押す。
2. 新しいファイルの確認欄で既存ルールの候補を確認する。
3. AIが設定済みなら「AIに分類候補を聞く」を押し、両方の候補を比較する。
4. 担当者が種類を確認・訂正する。重要な列や単位の変更は管理者の正式確認に進める。
5. AIの候補だけで予測結果が更新されないことを確認する。

## 次の実装単位

- 確定済み商品コード・JAN台帳と出荷原本を根拠に、複数JAN候補の順位と理由を提示する。
  候補外JANの生成や自動確定はしない。
- 箱・くくり・パレットの単位候補を表示し、換算値は担当者の確定履歴を優先する。
- 商品ごとの予測可否・不足情報画面に確認結果を接続する。
- 現行ルールのみの場合とAI併用時で、候補一致率、確認時間、予測可能商品数、
  誤提案件数を実データで比較する。改善が確認できるまで自動採用しない。
