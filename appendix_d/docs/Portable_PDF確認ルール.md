# PDF読取の取りやめと帳票別確認ルール（pilot.30）

未承認原本は、読取中・エラー後・確認中に取りやめできる。原本、成功済みページ、過去判断・抽出は削除しない。再開を明示操作する。送信済みAI処理は中断できず料金も取り消せないが、取りやめ後の応答は採用せず、残りページを送信しない。取取消状態と履歴はSQLiteに追加保存し、既存の承認済み原本は変更しない。

今回の印刷在庫帳票は現在欄を取得する。空欄＝0は帳票ごとにチェックしてAPI不要の読取を行った場合だけ適用する。現在ケース・バラの両方が空欄なら除外予定、片側だけ空欄ならその欄を0にする。元の空欄はsource_current_case/source_current_loose、選択ルールはblank_current_policyとして抽出履歴へ保存する。担当者が原本確認して保存するまで正式採用しない。当出・他帳票・一般CSV・AI読取の空欄≠0契約は維持する。

JAN行直後の括弧付き年月日はsource_detail_dateとして読取・表示・担当者確認に保存し、確認済み在庫CSVにも「商品名下の日付（意味未確認）」として渡す。同一JAN・賞味期限でもこの日付が異なる行をadapterで結合しない。製造日とする根拠は業務確認待ち。正式Phase 3Sの在庫識別は従来のJAN×location×賞味期限であり、製造日を加えた正式bucket拡張・migrationはこの版では実施していない。画面の日付保持と正式在庫identityの拡張を混同しない。

人工データで画像例の4明細、0除外、片側空欄、当出保持、同JAN同賞味期限の日付差、取取消後の遅延応答拒否、再開後の旧応答拒否、成功結果保持、承認済み保護を確認する。実データはRepositoryへ保存しない。
