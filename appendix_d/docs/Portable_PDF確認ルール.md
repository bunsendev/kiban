# PDF読取の取りやめと帳票別確認ルール（pilot.31）

未承認原本は、読取中・エラー後・確認中に取りやめできる。原本、成功済みページ、過去判断・抽出は削除しない。再開を明示操作する。送信済みAI処理は中断できず料金も取り消せないが、取りやめ後の応答は採用せず、残りページを送信しない。取取消状態と履歴はSQLiteに追加保存し、既存の承認済み原本は変更しない。

今回の印刷在庫帳票は現在欄を取得する。空欄＝0は帳票ごとにチェックしてAPI不要の読取を行った場合だけ適用する。現在ケース・バラの両方が空欄なら除外予定、片側だけ空欄ならその欄を0にする。元の空欄はsource_current_case/source_current_loose、選択ルールはblank_current_policyとして抽出履歴へ保存する。担当者が原本確認して保存するまで正式採用しない。当出・他帳票・一般CSV・AI読取の空欄≠0契約は維持する。

2026年10月9日の業務確認により、JAN行直後の括弧付き年月日は「ムロオ倉庫入庫日」と確定した。製造日ではない。既存保存との互換性のため内部キーsource_detail_dateは維持し、画面と確認済み在庫CSVの列名を「ムロオ倉庫入庫日」にする。出荷日・在庫基準日・賞味期限とは別管理する。同一JAN・倉庫・賞味期限でも入庫日が異なる行をadapterで結合しない。正式Phase 3Sの在庫識別は従来のJAN×location×賞味期限を維持し、入庫日は原本照合用の明細情報として保持する。ロット管理済みとは扱わない。

画像例の1行目は当出52ケース・バラ2で現在両欄が空欄のため在庫0として除外する。2〜4行目の現在在庫を取得する。当出を現在在庫の代わりに使わない。

人工データで画像例の4明細、0除外、片側空欄、当出保持、同JAN同賞味期限の日付差、取取消後の遅延応答拒否、再開後の旧応答拒否、成功結果保持、承認済み保護を確認する。実データはRepositoryへ保存しない。


## 2026-10-11 現場確認への対応

原本確認画面に未完成の途中保存を追加。空欄・不確定・除外理由を含めSQLiteへ追記し、原本・抽出・正式承認は変更しない。再読取でrevisionが変われば古い途中保存を適用しない。取消中・承認済みの原本には保存できない。

表示中の在庫行の空欄を0にする操作と、表示中のケース・バラの意味をまとめて確認する操作を追加。出荷の空欄は自動0にしない。最終承認は原本照合後に行う。商品名は複数行表示にし、末尾の商品名が見えるようにする。

正式取込の単位確認は、取込用CSVがCASEであることの確認。PDFのバラをそのまま箱とみなす確認ではない。PDF承認時にケース＋バラ÷入数で換算し、互換CSVの明細バラ数列へ換算後のCASEを渡す。原本数量と換算根拠は承認履歴に残す。

調整列は抽出履歴に保持し、現在列へ再加算しない。調整理由は帳票だけでは確定できず業務確認が必要。除外は未承認一覧のチェックを外せば再対象化できる。承認・受渡し済みデータの訂正版発行は別工程であり、この途中保存機能で上書きしない。


## pilot.32 訂正版
承認済み原本から確認者・理由付きで訂正版を作成する。元の原本、抽出、承認を不変に保持する。操作の再送は同じ訂正版を返す。元版は再受渡し不可。祖先版が受渡し済みなら訂正版も追加受渡し不可とし、二重計上を防ぐ。分析・正式Snapshotの自動置換は未実装。
