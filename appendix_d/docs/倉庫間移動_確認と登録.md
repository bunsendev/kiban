# 倉庫間移動の確認と登録

管理者向け。担当者画面の末尾「倉庫間移動を確認・比較（管理者）」を開く。

## 登録

専用CSVテンプレートをダウンロードし、UTF-8で保存する。ファイル名は任意。

| 列 | 内容 |
|---|---|
| event_id | その伝票の出庫／入庫側ごとに一意のID。再送時に変えない |
| event_date | 実際の出庫日または入庫日。YYYY-MM-DD |
| movement_kind | TRANSFER_OUT、TRANSFER_IN、CUSTOMER_SHIPMENT。不明は空欄 |
| transfer_id | 出庫側と入庫側で共通の元伝票番号・移動ID |
| line_id | 元伝票内の明細番号。両側で一致させる |
| product | JAN等の正式な商品識別子 |
| source_location | 移動元倉庫 |
| destination_location | 移動先倉庫 |
| quantity | 0以上の数量。空欄を0にしない |
| unit | CASE＝ボール、EACH＝バラ |
| source_file | 元データのファイル名 |
| classification_evidence | 区分コードの業務定義など分類根拠 |

確認者とCSVを指定し「確認した分類を登録」を押す。保存完了を表示する。名前や数量の一致だけで移動と決めない。不明行は要確認として保存する。

同じ移動の同じ明細を二重登録すると拒否する。別々の入庫に分割された伝票、取消・数量訂正はV1で自動処理しない。別IDを付けて元伝票を二重登録せず、管理担当者へ確認する。

## 確認・比較

期間を選び表示する。数量は商品×単位別。元伝票・原本SHA・行番号を詳細で確認できる。出庫済みでも入庫がなければ移動中として扱う。

導入前後の比較では、同じ営業条件・全伝票の存在を確認できた場合だけ確認欄を選ぶ。未識別あり、片側不明、導入前0は削減率を計算しない。観測日数は営業日数とは異なる。

台帳への登録は既存の現在在庫、確定済み予測を変更しない。既に移動を含む在庫へ二重加算しないためである。出荷履歴の需要分離には、元の出荷CSVへmovement_kind、transfer_id、source_location、destination_location、classification_evidence列を含めて新しく取り込む。移動先を推測して埋めない。

## 保存場所

- 台帳：Data/State/warehouse-transfers.sqlite3
- 原本：Data/State/TransferSources/<SHA256>.csv
- 既存出荷ZIPの除外根拠：Data/Analysis内の分析結果にtransfer_exclusionsを保存
- 履歴比較の根拠：Data/State/HistoryStudies内の新しい比較結果のprovenance

既存データを変更する前にDataフォルダ全体をバックアップする。原本・DBを開発Repositoryに登録しない。
