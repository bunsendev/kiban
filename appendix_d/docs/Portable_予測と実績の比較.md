# 元予測・担当者修正・確定実績（pilot.44）

現場画面下の「元の予測と実績を比較」を開き、予測履歴と対象期間を選んで比較します。同じ日の複数Runを混合しません。元予測は変更せず、担当者修正は空欄なら未設定です。

正式な日次出荷取込で、JAN・倉庫の対応が確認されたOBSERVEDと明示的なCONFIRMED_ZEROを確定実績として保存します。候補ZIP・未承認PDF・隔離行・欠測は確定実績にしません。在庫数量は出荷実績に使用しません。数量が異なる再取込は競合として対象外にします。

過去日は通常の数量変更不可です。確定済みと未確定は別の理由を表示します。当日は確定実績があれば変更不可。未確定の場合も、締め時刻が未設定なら保留します。日本時間の締め前のみ数量変更できます。未来日は理由を付けて変更できます。期間合計が過去日を含む場合も変更できず、未来日へ勝手に配分しません。感想の記録は可能です。

管理者は既存のWindows管理者設定起動から発行する15分の一時認証を使って締め時刻を設定できます。比較画面の管理者欄で日別の例外修正ができます。認証値はこの画面では保存せず、元予測・実績は変えません。理由・修正者・変更前後・対象日・記録時刻が履歴に残ります。期間合計の例外修正は、同じ認証を使用するreview APIをIT担当者が使用します。

誤差は実績−元予測。誤差率は誤差÷元予測×100で、元予測0は算出不可。MAEは平均絶対誤差、WAPEは絶対誤差合計÷実績合計×100で、実績合計0は算出不可です。修正値は精度集計に使用しません。商品別・日別の件数と指標、対象外の理由を表示します。少数データのみで実用精度は保証しません。

作成日時不明・商品/倉庫/単位不明・実績未確定・競合・予測欠損・対象日以降の再計算は集計から外します。古いProduction Runの完了時刻がDB補完された可能性があるため、新しい履歴収録版のない旧Runは作成日時を推測しません。単位等が未確認の簡易CSV Runや参考需要はそのまま別履歴に残し、正式データと無条件に照合しません。

更新前はアプリを終了しData全体をバックアップしてください。追加のData/State/forecast-verification.sqlite3が検証台帳です。既存のresult-feedback.sqlite3とfield-ui.sqlite3は変更履歴を保持します。更新後のDataを旧版へ戻すより、更新前バックアップへ復帰してください。別PCのDataは共有しません。
