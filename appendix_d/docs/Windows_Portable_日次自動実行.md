# Windows Portable 日次自動実行

## 目的

現場担当者が投入した在庫・出荷ZIPを、分析、担当者確認、正式在庫取込、
出荷日次化、14日予測まで同じ日次実行として追跡します。業務判断を自動で
補完せず、確認が必要な工程では理由を表示して停止します。

## 操作

1. ランチャーの「投入フォルダを開く」を押し、`Data/Incoming` へZIPをコピーします。
   コピー後に同じサイズ・更新日時が2回続いたことを確認して自動分析します。急ぐ場合は
   画面の「今すぐ投入ファイルを確認」を押します。画面から直接ZIPを選ぶ従来操作も使えます。
2. 「確認が必要なデータ」がある場合は、JAN対応、賞味期限欠損、除外を判断します。
3. 「最新在庫を正式取込用に準備」で、正式拠点コード、拠点名、在庫基準時刻、
   `明細バラ数 = CASE` を確認します。
4. 「日次処理を予測まで続ける」で、確認者と理由を入力し、次の4項目を確認します。
   - 倉庫ごとに最大20商品のPilot対象
   - 隔離0件、原本数量と正規化数量の一致
   - JANと正式倉庫コードの予測上の対応
   - 出荷CSVが存在し対象JANがない日の出荷0箱扱い
5. 「確認済み工程を予測まで実行」を押します。

完了すると対象系列数と結果保存リンクを表示します。途中で画面やPCを閉じても、
同じ分析結果を開くと保存済み成果物から再開します。

## 投入ファイルの保管

- 待機中: `Data/Incoming/*.zip`
- 受付済み原本: `Data/Incoming/Processed/`
- 受付できなかった原本: `Data/Incoming/Rejected/`
- 受付結果と理由: `Data/Incoming/Receipts/*.json`

不正ZIP、空ファイル、100 MB超のファイルは正式処理へ渡さず、理由付きで
`Rejected`へ移します。処理中や終了処理中は元ファイルを移動せず、次回確認時に再試行します。
ファイル名が同じでも内容のSHA-256を実行IDに使うため、同じ内容を再投入しても
分析・日次実行は重複作成しません。

## 安全停止

| 表示 | 意味 | 次の対応 |
|---|---|---|
| 確認待ち | JAN、賞味期限等に未確認行がある | 手順2で判断する |
| 正式在庫の確認待ち | 拠点、基準時刻、数量単位が未確認 | 手順3を行う |
| 正式在庫を隔離 | JAN、賞味期限、数量等を正式化できない | 隔離理由を確認する |
| 予測条件不足 | 履歴28日未満、直近欠測、在庫と出荷の基準日不一致等 | 停止理由を確認する |
| 予測完了 | 確認済み系列の予測を保存済み | 結果を確認する |

停止中の系列を0として補完したり、未確認の担当者判断を自動採用したりしません。

## 保存と再現性

- 実行IDは入力ZIPのSHA-256です。
- 進捗は `Data/State/DailyAutoRuns/<実行ID>.jsonl` へ追記します。
- 各版は一つ前のSHA-256を保持し、改変を検出します。
- 同じ確認内容で再実行した場合は、正式在庫登録と予測成果物を重複作成しません。
- 原本ZIP、担当者判断、正式在庫、予測結果は既存の保存場所と契約を使います。

## 開発時の確認

```powershell
python -m pytest tests/portable/test_p1_flow.py -k daily_run -q
python -m pytest tests/portable/test_p1_flow.py -q
```

APIは `GET /api/daily-runs/{analysis_id}` で現在の再開点を返し、
`POST /api/daily-runs/{analysis_id}/advance` で明示確認済み工程を進めます。
投入フォルダは `GET /api/drop-folder` で状態を確認し、
`POST /api/drop-folder/scan` で明示的に再確認できます。
