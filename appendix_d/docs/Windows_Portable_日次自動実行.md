# Windows Portable 日次自動実行

## 目的

現場担当者が投入した在庫・出荷ZIPを、分析、担当者確認、正式在庫取込、
出荷日次化、14日予測、Production予測、倉庫別日次サマリー、到着時点在庫、
推奨出荷のSHADOW試算、担当者判断まで同じ日次実行IDで追跡します。
業務判断を自動補完せず、確認や正式入力が必要な工程では理由を表示して停止します。

## 操作

1. ランチャーの「投入フォルダを開く」を押し、`Data/Incoming` へZIPをコピーします。
   コピー後に同じサイズ・更新日時が2回続いたことを確認して自動分析します。急ぐ場合は
   画面の「今すぐ投入ファイルを確認」を押します。画面から直接ZIPを選ぶ従来操作も使えます。
2. 「確認が必要なデータ」がある場合は、JAN対応、賞味期限欠損、除外を判断します。
3. 「最新在庫を正式取込用に準備」で、正式拠点コード、拠点名、在庫基準時刻、
   `明細バラ数 = CASE` を確認します。
4. 「日次処理を続ける」で、Pilot対象、数量一致、JAN・倉庫対応、出荷0箱policyを確認します。
5. 「Production予測まで実行」を押します。正式取込、日次化、14日予測、Production予測を
   順に実行します。実行中は画面が自動更新され、PCや画面を閉じても同じ実行IDから再開します。
6. Production予測完了後、賞味期限の最低残日数と注意日数を確認し、日次サマリーを作成します。
7. 画面から入力テンプレートZIPを保存し、次の4つのCSVへ確認済み情報を入力します。
   - `factory_inventory.csv`: JAN別の工場在庫と基準日時
   - `production_plans.csv`: 生産予定（ない場合は見出し行だけ）
   - `routes.csv`: 工場から倉庫までの12〜36時間の配送policy
   - `safety_stock.csv`: 倉庫別の安全在庫日数と出荷単位（CASE）
8. 入力ZIPを選び、「正式入力を検証して試算」を押します。不足や対象外は0にせず、
   理由を表示して停止します。修正済みZIPを同じ画面から再投入できます。
9. 到着予定時点までの需要を差し引いた在庫とSHADOW推奨出荷量を確認します。
   商品・倉庫ごとに採用、増量、減量、見送り、本日は出荷しない、の判断を保存します。

全件を確認すると日次実行は「完了」になります。SHADOW値は参考情報であり、正式な
出荷指示を自動発行しません。

## 安全停止と再開

| 表示 | 意味 | 次の対応 |
|---|---|---|
| 確認待ち | JAN、賞味期限等に未確認行がある | 担当者判断を保存する |
| 正式在庫の確認待ち／隔離 | 拠点、基準時刻、単位、正式化可能行に問題がある | 理由を確認して再準備する |
| 予測条件不足 | 履歴28日未満、直近欠測、基準日不一致等 | 停止理由を確認する |
| Production予測を実行中／停止 | 正式予測の処理中、またはWorkerが失敗 | 完了を待つか失敗理由を確認する |
| 日次サマリー確認待ち | Production予測済み、賞味期限条件が未確認 | 条件を確認して作成する |
| 正式Decision入力待ち／隔離 | 工場在庫、route、安全在庫等が未入力または不整合 | テンプレートを修正して再投入する |
| 推奨出荷を停止 | 正式入力は読めたが計算対象がない | 商品別・倉庫別理由を確認する |
| 推奨出荷の確認待ち | SHADOW試算済み | 各推奨への担当者判断を保存する |
| 完了 | 全推奨の担当者判断を保存済み | 必要に応じ後日実績を登録する |

停止中の系列、工場在庫、生産予定を0として補完しません。修正後は同じ分析結果から再開し、
既に作成済みの正式在庫、予測、サマリーを重複作成しません。

## 投入ファイルと証跡

- 待機中: `Data/Incoming/*.zip`
- 受付済み／拒否原本: `Data/Incoming/Processed/`、`Data/Incoming/Rejected/`
- 日次進捗: `Data/State/DailyAutoRuns/<実行ID>.jsonl`
- 正式予測・日次サマリー: `Data/FormalForecast/`
- Decision入力原本・検証結果: `Data/FormalForecast/DecisionInputs/`

## 画面から工場・配送条件を入力する

日次画面は、予測対象になった倉庫数と商品数を先に表示する。担当者は確認済みの
工場コード、工場在庫基準日時、12〜36時間の配送時間、安全在庫日数、出荷単位、
商品ごとの工場在庫（箱）を入力する。空欄は0箱へ変換せず、対象商品が1件でも
不足していれば正式入力を作成しない。

画面入力は内部で既存の4 CSVから成る正式Decision入力ZIPへ変換し、ZIP取込と同じ
検証、原本SHA-256、隔離、内容アドレス保存を通す。複数工場、倉庫ごとに異なる
route、生産予定を扱う場合は「複数工場・生産予定・倉庫別条件をZIPで入力」を開く。
画面入力とZIP入力のどちらもSHADOW試算であり、正式な出荷指示を発行しない。
- 推奨出荷・担当者判断: 既存のShipment Recommendation／Review台帳

実行IDは入力ZIPのSHA-256です。進捗は前版SHA-256を含む追記型JSONLで、原本や
既存成果物を上書きしません。同じ確認内容を再送しても同じ成果物を返します。

## APIと開発確認

- `GET /api/daily-runs/{analysis_id}`: 現在状態と再開点
- `POST /api/daily-runs/{analysis_id}/advance`: 正式予測まで進める
- `POST /api/daily-runs/{analysis_id}/daily-summary`: 日次サマリーを作成
- `POST /api/daily-runs/{analysis_id}/decision-inputs`: 正式入力を検証してSHADOW試算
