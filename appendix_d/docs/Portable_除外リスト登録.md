# 対象外商品リストの登録

担当者画面のPDF・画像の確認欄にある「対象外商品の登録・解除」を開きます。

1. JSON、CSV、PDF、PNG、JPEGのリストを選びます（10 MB・1000明細以内）。
2. 必要なら登録済みの商品マスターを選択します。名前が一意に一致する場合はJAN候補を補完します。
3. 「ファイルから候補を読み取る」を押します。CSVと対応する文字入り在庫PDFは端末内で読み取ります。画像・手書きPDF等はAPIキー設定とOpenAI送信への同意が必要です。API料金が発生します。
4. 一覧のJAN・商品名・対象外指定を原本と照合します。不明なJANは補完・修正し、登録する行にチェックします。読み取れなかった行を自動登録しません。
5. 確認者と照合チェックを入力して「確認した商品設定を登録」を押します。全明細を取得できなかった場合は、確認済み商品の部分登録を明示的に選択します。

CSVの見出し例：JAN,商品名,理由。文字コードはUTF-8またはCP932です。13桁JANのチェック桁を検証します。名前のみのCSVも候補を表示しますが、JAN確認後に登録します。短いコードからJANを推測して登録しません。同一JANで対象外と解除が衝突するリストは拒否します。

読取段階では除外設定は変わりません。登録後は未承認のPDF確認と承認時の対象判定に反映されます。既に承認したデータ・予測や直接CSV入力を遡って変更しません。「対象へ戻す」で解除できます。

原本・読取候補はその端末のData/State/product-exclusions.sqlite3に保存し、登録履歴と原本SHA-256を紐付けます。このDBには商品情報と原本が含まれます。通常のログに原本やAPIキーを出しません。原本はローカルに保持し、AIを選んだ場合に限り読取のためOpenAIへ送ります。

人工データによる機能検証を行っています。画像・手書きの読取精度は原本との照合が必要です。
# JAN先頭7桁の条件（pilot.41）

個別JANに加えて、有効な13桁JANの先頭7桁による除外条件を保存する。未登録の新しい商品にも一致する。6桁の表示コードやチェック桁不正のJANは条件で隠さず、通常の確認対象に残す。

設定JSONのv2形式は、従来の`products`に加えて`prefixes`を持つ。例：`{"format":"bunsen-product-exclusions-v2","products":[],"prefixes":[{"prefix":"4901234","exclude":true,"reason":"人工例"}]}`。v1の既存ファイルも読み込める。v2は「設定JSONを登録（個別・先頭7桁条件）」から明示確認後に登録する。アプリフォルダーの`対象外商品設定.json`も起動時に一度だけ登録する。

原本の在庫・出荷文書の確認一覧と、文書からの新規受渡しに適用する。過去の承認済みファイル、既存予測結果、既に受渡し済みのデータを遡って削除しない。CSV ZIPの既存分析履歴・正式取込の対象範囲をこの変更だけで書き換えない。

画面では個別と先頭7桁の条件を区別し、条件を解除するときは確認者を入力する。個別除外を解除しても、有効な先頭7桁条件に一致する場合は対象外のまま。先頭7桁条件を解除しても個別除外は残る。同一設定JSONは繰り返し登録せず、再起動で解除を取り消さない。原本、読取値、除外前の手動保留、設定イベントを保持する。
