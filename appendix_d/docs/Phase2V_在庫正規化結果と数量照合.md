# Phase 2V 在庫正規化結果と数量照合

## 目的

Phase 2Uで保存した在庫正規化結果を現場担当者が画面で確認し、採用した元数量と正規化後数量の一致を確認してCSVとして取得できるようにする。

## 数量照合

Workerは隔離されなかった入力行の数量合計と、日付・JAN・倉庫・単位別に集約した数量合計を同一transactionで`inventory_normalization_summaries`へ保存する。APIは文字列表現の両数量と一致判定を返す。隔離行は採用数量へ含めず、理由別件数をジョブ台帳から表示する。

文字コード、必須列、対象ファイルなどの異常でジョブ全体が失敗した場合は結果を公開しない。過去の成功ジョブでも数量照合情報がない場合は、照合済みとして扱わず409を返す。

## API

- `GET /api/inventory-normalization-jobs/{job_id}/results`: READ権限。`limit`と`offset`によるページ取得、件数、数量照合を返す。
- `GET /api/inventory-normalization-jobs/{job_id}/results.csv`: EXPORT権限。全結果を決定的な順序のUTF-8 BOM付きCSVで返す。

CSV列は在庫日、JAN、倉庫コード、単位、数量である。元ファイル名、商品名、商品コード、絶対pathは含めない。

## 画面

`/ui/intake`は全件正規化の完了後、ファイル数、採用・隔離行数、隔離理由、数量照合、正規化結果件数と先頭20件を表示する。全結果は「正規化結果CSVをダウンロード」から取得する。表はDOMの`textContent`で構築し、業務値をHTMLとして解釈しない。

## 検証範囲

人工データで数量一致、ページング、安定した並び順、BOM付きCSV、未完了ジョブ、認証を確認する。実業務データの受入には、全143商品の確認済みJAN対応表を用いた全件実行後、隔離理由と数量一致を担当者が確認する必要がある。
