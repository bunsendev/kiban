# 学習データのバックアップと復元

Windows Portable版。現場担当者画面の「学習データのバックアップ・復元」、または「このPCの設定」から開きます。

## 再インストール前

1. 分析・取込・確認保存を終えます。投入フォルダへのコピーも終えてください。
2. 「バックアップZIPを保存」を押します。
3. ブラウザのダウンロード先を確認し、ZIPをUSBメモリ等、アプリのフォルダ以外にも保存します。

ZIPには確認・修正履歴、JAN対応、除外設定、学習用履歴・比較結果、原本、予測結果を含みます。業務データを含むため適切に保管してください。APIキー、送信用Token、管理者セッション、端末設定・未送信キューは学習バックアップに含めません。

バックアップを作成する前に消失したデータは復元できません。旧版のアップデート時に保存された `Data-backup.zip` が残っている場合は利用できます。

## 再インストール後

1. 再インストールしたアプリを起動し「学習データのバックアップ・復元」を開きます。
2. 保存したZIPを選び「内容を検証」を押します。
3. 作成日時・版・ファイル数を確認します。現在のデータへ足し込む機能ではなく、バックアップ時点への置換復元です。
4. 置換復元の確認欄を選びます。旧形式の場合は「作成時ハッシュなし」の確認欄も選びます。
5. 「このバックアップから復元を予約」を押します。
6. ブラウザだけでなく、ブンセンのランチャーを終了します。もう一度「ブンセン予測を起動.cmd」を実行します。
7. 同画面の「復元結果」で完了を確認し、除外設定、確認・修正履歴、比較結果を確認します。

予約後はデータの変更と自動投入の受付を止めます。再起動前なら「復元予約を取り消す」で解除できます。起動中のDBを上書きしません。

現在のPCの端末ID・ログ送信設定・未送信キューを維持します。APIキーやTokenは同じWindowsユーザーでも設置先の変更等で再設定が必要になることがあります。設定画面で保存状態を確認してください。

## 検証と対応形式

- 新形式：`bunsen-learning-backup-v1`。一覧、SHA-256、ZIPのCRC、展開サイズ、パス、DB整合性・アプリの初期化を検証します。
- 旧形式：Data直下の内容をZIPにしたもの、または先頭が `Data/` のZIP。作成時ハッシュ・版は不明のため、確認の上でCRCとDB整合性を検査します。
- 256 MiB以下、展開後2 GiB以下。アプリ本体を含む配布ZIP、暗号化ZIP、リンク、不正なパス、新しい版のバックアップは受け付けません。
- 「内容を検証」はZIP・ハッシュ検査です。旧DBの整合性等は次回起動時にも確認し、失敗時は元データを維持します。

Data内の学習・業務ファイルを対象とします。外部PostgreSQLや外部フォルダ、Windowsの資格情報保管領域は対象外です。別の場所への復元では、古い正式Runの外部パス・外部接続はIT担当者が確認してください。過去の承認済み成果物を再署名・書換えしてパスを変更する処理は行いません。

## 復元に失敗した場合

復元結果の詳細をIT担当者へ伝えてください。現在のDataと復旧用フォルダは削除しないでください。別のバックアップを検証し直して再試行できます。退避データを戻す操作自体が失敗した場合は、空のDataで起動せず停止します。復旧用フォルダを保全し、アプリを起動し直してください。

復元前のDataは、設置フォルダ内の `BunsenRecovery-<識別値>/<復元処理ID>/previous-Data` に退避します。正確なパスは画面に表示します。起動時に途中停止を検出した場合、置換が完了していなければ退避済みDataへ戻します。

復旧用フォルダには作成ZIP、検証用ZIP、復元予約、処理結果、退避データが残ります。アプリの再配布ファイルやGitHubへ含めないでください。復旧確認後の整理はIT担当者が行ってください。
