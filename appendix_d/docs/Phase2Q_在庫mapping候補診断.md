# Phase 2Q 在庫mapping候補診断

## 目的

在庫CSVのヘッダー存在だけで列を決めず、値の充足、型、符号、列間一致をサンプル集計し、
在庫mapping候補を根拠付きで提示する。

## 診断契約

在庫構造診断は各CSVの先頭100行を読み、原値を保存・返却せず次を集計する。

- ファイル名末尾の`_YYYYMMDD.csv`に一致するファイル数
- 商品コード、商品名、明細バラ数、明細倉庫コードの値あり件数
- 明細バラ数の数値件数と非負件数
- ヘッダ倉庫コードと明細倉庫コードの一致件数

全ファイル名から日付を取得でき、全サンプル行で数量が数値かつ非負、倉庫コードが一致する場合、
次を候補として返す。

- 日付: ファイル名の8桁日付
- 商品: `商品コード`、`商品名`
- 数量: `明細バラ数`
- 拠点: `明細倉庫コード`

単位は自動決定しない。JAN列がないため、商品コードからcanonical productまたはJANへの版付き
対応付けも別途必要である。

## 実データ結果

在庫CSV 1,926件の各先頭100行、合計186,166行を診断した。全ファイルで日付を取得でき、
商品コード、商品名、明細バラ数、明細倉庫コードは全サンプル行に存在した。明細バラ数は
全件数値・非負で、ヘッダ倉庫コードと明細倉庫コードは全件一致した。

この結果は列mapping候補の技術判定であり、`明細バラ数`の業務上の単位と商品コード対応を
承認するものではない。
