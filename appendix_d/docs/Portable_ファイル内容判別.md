# フォルダ投入とファイル内容の判別

2026-10-05。0.6.0-pilot.10でCSV確認画面と任意のAI列対応提案を追加。旧pilot.9には未収録。

## 担当者の操作

1. ランチャーで「投入フォルダを開く」を押す。
2. 在庫・出荷CSVをそのまま `Data/Incoming` 直下へまとめてコピーする。ZIP作成は不要。従来のZIPも使用できる。
3. コピー後10秒間ファイルの一覧・サイズ・更新日時が変わらなければ、CSVをまとめて分析する。
4. 担当者画面の「投入フォルダから読み込む」で受付済みの分析を開く。判断が必要な商品を確認し、予測へ進む。

在庫だけの場合は出荷CSVを待つ。分析には今回使う出荷履歴も一緒に投入する。過去の受付との自動結合は行わない。
Processed・Receipts・Rejectedの中には入れない。フォルダの下位階層は監視しない。
ブラウザの直接アップロードは引き続きZIP。CSV直接投入はフォルダ経由を使う。

## 判別方法

- ファイル名の「出荷」「在庫」の文字ではなく、CSVの列構成で種類を判別する。
- 出荷：出荷日・JAN・数量。在庫：商品コード・明細バラ数・賞味期限。
- 倉庫は倉庫・倉庫名・拠点列、基準日は基準日・基準日時・データ基準日列から読む。
- 既存の「神戸日時出荷_20260204.csv」等は従来の倉庫名・日付取得も継続する。
- 内容に倉庫と基準日があれば、export001.csv等の任意のファイル名を使える。
- 出荷行の日付だけから、他の商品が存在しない日を出荷ゼロとは認定しない。
- 両方の種類に一致する列、複数の倉庫表記、不明な倉庫、在庫基準日の欠落などは投入画面に理由を表示する。ファイル名を倉庫と推測したり、投入日時を在庫日時に置き換えたりしない。

原本CSVは内容を変えず内部ZIPにも保存する。分析成功後にProcessedへ移動する。
コピー後に元CSVが変更された場合は移動せず、次回確認へ残す。
受付完了と正式取込・予測完了は別。数量単位・JAN等の既存確認は維持する。

## 今回の対象外

複数倉庫を含む単一CSVの分割、Excel、PDF、写真・手書き認識は今回の追加に含まない。
列対応を画面で確認すると、同一の列構成に限って再利用できる。固定入力した倉庫・基準日は元ファイルのSHAが異なる場合には再利用しない。承認はSQLiteに追記し、内部ZIPには原本（Originals）と承認情報（Approvals）を同梱する。

AI提案は既存OpenAI Responses API接続を利用し、列名のみ送信する。キーは画面入力・非保存。提案だけで採用せず、利用者が保存した列対応のみ取り込む。単位・換算率を推測して適用しない。実API疎通はキー未入力のため未検証。

## 検証

人工データで、任意名の在庫・出荷CSV、CP932/UTF-8 BOM、正式在庫の倉庫取得、正式出荷の日付取得、原本バイト保存、CSVまとめ受付、在庫のみの待機、倉庫情報不足、欠測とゼロの区別を検証する。
実データの新形式・現場PCでの動作検証は未実施。
