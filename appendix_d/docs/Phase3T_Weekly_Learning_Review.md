# Phase 3T 週次改善レビュー

## 目的

SHADOW運用で記録したSystem参考値、担当者判断、後日実績を7日単位で固定し、改善候補を人が確認する。週次結果や候補から予測モデル、特徴量、lead time、安全在庫、出荷単位を自動変更しない。

## 操作

1. Portable画面の手順11で後日実績を保存する。
2. 手順12で週の終了日と対象Pilot Scope版を選ぶ。
3. 集計版、判定基準版、候補化する最小根拠件数、確認者、集計基準日時を入力する。
4. SHADOW週次確認であることを選択して集計版を作成する。
5. 比較可能件数、MAE・RMSE・WAPE・Bias、担当者修正、欠品・期限切れ・倉庫間移動、実績未取得件数を確認する。
6. 改善候補を次工程の調査対象として承認するか、今回は却下する。判断理由を必ず記録する。

## 集計契約

- 期間は終了日を含む連続7日間。
- Pilot Scope版、集計版、判定基準版、`known_at`を固定する。
- `known_at`より後に判明した担当者判断・実績・訂正版は、その集計版に混ぜない。
- 同じ入力からは同じ`review_id`と`content_sha256`を作る。
- 前週も同じScopeと同じ`known_at`で集計し、両方が算出済みの指標だけ差を表示する。
- 空欄は未取得、文字列`0`は確認済みゼロ。実績未取得を0へ補完しない。

## 改善候補

担当者理由と業務Outcomeを次の調査対象へ対応付ける。

| 観測 | 候補 |
|---|---|
| 販促・季節理由 | カレンダー特徴 |
| 大口予定理由 | 大口予定入力 |
| 生産制約 | 生産予定連携 |
| 配送制約・倉庫間移動 | Route Policy |
| 賞味期限懸念・期限切れ | 賞味期限・FEFO Policy |
| データ誤り・実績未取得 | データ品質 |
| 欠品懸念・欠品実績 | 欠品防止Policy |

候補は根拠case数、影響数量、理由code、根拠case IDを持つ。承認・却下はrevision付きの追記eventであり、過去判断を上書きしない。承認は調査を進める判断であり、設定変更の承認ではない。

## 監査と制約

- 週次集計、候補、判断eventはcontent hash付きで保存する。
- Portable担当者判断を既存`field_learning`台帳へ同期し、System・Operator・Actualを同じcase IDで集計する。
- 週次集計の再送は同じ版へ収束する。候補判断は`expected_revision`で競合を拒否する。
- 実データ、商品名、原本path、資格情報をRepositoryへ保存しない。
- 欠測の原因、担当者判断とOutcomeの因果関係、候補の改善効果は本機能だけでは確定しない。
