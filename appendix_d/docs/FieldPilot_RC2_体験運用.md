# Field Pilot RC2 体験運用

配布版: `0.1.0-field-pilot.2`。目的は、現場担当者が日々の作業で画面を触り、操作上の問題を記録して改善につなげること。正式な出荷判断の切替や予測精度の受入ではない。

## 担当者の一日の流れ

1. デスクトップの「ブンセン データ投入」に、管理者が指定したCSVまたはPDFをコピーする。
2. 「ブンセン 出荷予測」を開く。画面を開いたまま追加投入した場合は「投入したファイルを確認」を押し、Windowsの確認画面で続行する。
3. 受付件数、確認待ち、形式候補、正式在庫ジョブの状態、参考結果の更新日時を確認する。ルール未設定でも受付・確認待ち件数は表示されるが、正式取込済みとは扱わない。
4. 候補の種類が分かる場合は画面で確認する。確定済み商品だけをPilot対象に選び、未確定商品は管理者画面の一覧からJANを照合する。数値の正式採用と予測更新は別の判断である。
5. 困った操作と理由を選んで記録する。ファイル名、商品名、自由記述は入力しない。
6. 終業時に「本日の作業を完了」を押してバックアップと許可済み改善データの送信準備を行う。

画面が `DATA_NOT_READY` の場合も、ファイル投入、件数確認、形式候補の確認、操作フィードバックを試せる。予測結果が新しいファイルから自動更新されたとは表示しない。担当者は従来の業務手順と判断を継続する。

## 管理者が確認すること

- 導入後、実機で起動・再起動・追加投入・終業・バックアップ・復旧を確認する。
- `inbox-policy.json` の必須ファイルと拠点を設定する。初期状態は `UNCONFIGURED`。正式な入力mapping版、Pilot Scope版、Intake版を設定した既知の在庫CSVだけが、投入後に独立WorkerのSnapshotジョブへ送られる。
- 管理画面でジョブの採用候補行数、隔離行数、照合結果を確認する。隔離行がなく照合が一致した最新ジョブだけ、管理者が版を指定して承認できる。新しい投入がある場合、古い承認で当日分を準備完了にしない。
- JAN未確定の商品は管理画面の「未確定の商品」に表示する。現場設定へのJAN登録は版付きの確認記録であり、正式な商品mapping版とPilot Scope/Intake版への反映は管理者の別作業となる。対象外商品を推測して採用しない。
- 改善イベントはPC内の `Data/Inbox/improvement-events.sqlite3` に保存される。終業時の外部共有はPrivacy PolicyとToken・公開鍵の設定に従い、既定では診断集計を送らない。
- 必要な範囲だけPrivacy Policyを有効化し、共有サーバーで集計を確認する。個別の原本・JAN・商品名はこの操作フィードバックには記録しない。
- `bunsen-pilot-scan://run` の実機登録とブラウザー確認画面は新規導入環境で受入確認する。画面から動かない場合はデスクトップの「ブンセン 出荷予測」を再実行する。

## 現時点の境界

既知の在庫CSVについては、投入から正式Snapshotジョブ生成、検証状態表示、管理者承認まで接続した。出荷実績の正式取込、予測Runの自動起動、結果更新は未接続。現場設定のJAN登録を正式mappingへ自動反映する経路も未接続である。PDFは人間確認を経ず正式在庫として採用しない。Field Pilot画面は読み取り専用のShadow結果であり、出荷指示を確定・送信しない。RC1の受入結果は履歴として保持し、RC2の実機受入を別途記録する。
