# 例外優先の文書確認と単位ルール

ボール=ケース、バラ=商品1個の確認を、対応印刷帳票・倉庫・適用開始日・マスター版の範囲で再利用する。入数・数量・日付・JANを推測せず、原本抽出と正式承認を変更しない。

未承認文書の行を「機械点検通過・文書承認待ち」「例外確認」「処理保留」「除外予定」に分類し、既定一覧を例外優先にする。例外・保留が0行で点検通過行がある場合は、点検通過の明細を初期表示する。表示0行の場合は、抽出なし・条件不一致・全行除外を区別し、表示条件を解除するボタンを案内する。点検通過は読取正解率や正式採用の保証ではない。対応印刷帳票の構造網羅性、数量収支、形式、単位、重複等を確認し、AIのcompleteだけで通過させない。旧抽出で構造点検がない場合は例外にする。

単位確認は対象・条件・変更予定をプレビューしてから適用し、途中保存する。版・編集・取消状態が変われば拒否。ルール作成者・理由・適用範囲と適用結果を追記保存し、無効化は将来の再利用だけを止める。新規原本で条件が同じなら単位確認を再利用するが、文書承認と受渡しは自動実行しない。

入数の自動流用、AI原本の無条件確認省略、正式結果の置換、精度100%の表示は対象外。原本ページの比較画像は別生成し、行座標がないものはページ単位で表示する。

CSV履歴は同じ本文でも基準日が異なれば別候補として保持。旧履歴のキーは読取時に再索引し、失われた候補は保存原本から明示的に再集計する。原本・承認・予測は変更しない。

## pilot.52：一括PDF読取と空欄ルール

初回の印刷PDFで「この帳票の現在欄は空欄＝0」を選び、「印刷在庫表の列を取り直す（API不要）」を押す。原本の現在欄と照合した後、「読取ルール（単位・空欄）を確認・保存する」を開く。確認者・理由・適用開始日を入力し、次回再利用と「次回の一括読取も、この範囲の現在欄は空欄＝0」を選ぶ。対象をプレビューし、「この範囲に適用して途中保存」を押す。今回の文書承認は別に行う。

次の原本は「未読取の印刷PDFを一括読取（API不要）」で、帳票・倉庫・選択マスター版・適用開始日が一致する保存ルールを利用する。マスター未選択で保存したルールは、未選択の範囲だけに適用する。PDF内の在庫行すべてに条件が一致する場合だけ現在欄を補完する。保存ルールがない、無効、旧版、別倉庫・別マスター・開始日前・未対応帳票なら、空欄を未確認のまま残す。既存の単位だけのルールから空欄の意味を推測しない。

現在の両欄が空欄の在庫行は理由付きで除外するが、当出の出荷実績は残す。当調、入数、JAN、日付、読み取れた数量は変更しない。適用版と選択マスターを抽出履歴に保存する。読取後に適用ルールが失効・更新されたり、マスターを切り替えたりした場合は承認を止め、原本の読取から確認し直す。部分採用でこの条件を回避できない。既存承認や予測は書き換えない。

## pilot.52：通常行の簡易表示

機械点検通過行は商品・JAN・数量・基準日・賞味期限・倉庫入庫日・倉庫・原本ページを簡易表示する。「この明細の詳細を開く」で入力欄を表示し、「原本ページと比較」で原本と見比べる。「通常行も詳細表示する」で従来の編集表示にも切り替えられる。例外・保留は詳細入力のまま表示する。

詳細を開くだけでは値や承認状態は変わらない。値を修正した行は例外確認に戻し、機械点検通過だけを見ていた場合も確認対象へ表示を切り替える。数量・換算・空欄の検査と文書単位の確認・保存・受渡しは維持する。2日分登録しただけの完全自動承認は行わない。
