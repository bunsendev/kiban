# 印刷在庫表の読取点検（pilot.40）

PDFの「印刷在庫表を読み取る（API不要）」を実行すると、原本読取時の点検結果を一覧の上に表示する。

- 在庫明細数、数量収支一致・不一致・計算不能・未点検の件数。
- JAN、倉庫、商品名、在庫基準日、賞味期限、ムロオ倉庫入庫日の不足・形式不正。
- 同じJAN×倉庫×在庫基準日×賞味期限×倉庫入庫日の複数明細。

数量収支は「前残＋当入－当出＋当調＝現在」を、空欄=0・C入を換算係数と仮定して診断する。この仮定は正式単位や需要実績の確定ではない。原本の空欄と数量を変更せず、当調を現在在庫へ再加算しない。当調を出荷実績に自動転用しない。

点検結果は編集後の再計算ではなく、読取時の証跡として保存する。ページ別再読取ではそのページの証跡だけ差し替え、以前の読取履歴を保持する。AIページとの混在時は収支未点検数を示す。正常件数は全項目の目視照合や担当者承認を意味しない。

同条件の複数行は原本上でも別明細になり得るため、自動削除・重複判定キーによる上書きをしない。数量異常は原本を開いて確認する。登録済み対象外商品は通常一覧から分けるが、原本と設定履歴を保持する。

配布用の担当者指定対象外設定は、実データとしてリポジトリ外で同梱する。新規PCで1回だけ登録し、同じ設定ファイルの再起動時再取込で担当者の解除判断を上書きしない。マスター未登録商品の対象判定、CSVの数量単位、当調の用途、拠点名対応、締め時刻は自動確定しない。
