# Field Pilot RC1 管理者の初回設定

この手順は現場担当者ではなく、管理担当者が実施する。配布判定がGOになるまで現場業務の判断には使用しない。

1. 別紙のSHA-256とInstallerのSHA-256を照合し、現場PCでInstallerを実行する。Windows 64 bit、WSL 2、Docker Desktopの準備と社内利用条件を確認する。管理者権限や再起動が必要になった場合はPC管理者が対応する。
2. 初回の接続設定案内で `y` を選び、共有サーバーの公開鍵PEMの保存先と送信用Tokenを入力する。Tokenは画面に表示されず、現在のWindowsユーザーのDPAPIへ保存される。Tokenを配布物、メール、手順書へ書かない。再インストールでは再入力不要だが、別ユーザー・PC交換・Token失効時は再設定する。
3. デスクトップの「ブンセン Feedback Server 接続テスト」で、業務値を含まない暗号化PackageのACKを確認する。既存の疎通確認と、RC1の認証付き送信確認を区別する。
4. Pilot対象商品のJANだけを対象範囲として確認し、対象範囲の全件が確定していることを確認する。全商品JANの確定はShadow開始条件としない。
5. 現場設定のInventory Time Policyを、在庫の基準時刻と許容遅延について業務承認済みの値にする。Required File Policyに日次必須ファイルの種別と正式schemaを設定する。未確認値を推定で入力しない。
6. Privacy / Feedback Policyの項目・版・合意を管理画面で設定する。初期状態は送信OFF。原本やJAN原値は通常送信しない。
7. Pilot Scope、承認済み在庫、確定予測Run、FEFO、当日の鮮度を照合する。Shadow画面がREADYであることを確認する。画面に不足や確認待ちがあれば、Field Pilot準備完了としない。
8. バックアップ、終業時送信、オフライン時のOutboxと次回再送、PC再起動後の保持をAcceptance表に記録する。実サーバーの保存先確認には権限を持つ管理者が立ち会う。

現行RC1では、単一フォルダに置いたCSV/PDFから正式取込、予測更新までの自動接続は未完成である。ファイル分類の `RECEIVED` は正式採用を意味しない。管理担当者が既存の正式取込・承認経路を用いて更新するまで、古い結果を今日の結果として見せない。これが解決しない限り「ファイル投入だけで翌日の予測が更新される」という運用では配布しない。
