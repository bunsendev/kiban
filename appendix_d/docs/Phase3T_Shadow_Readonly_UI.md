# Phase 3T 倉庫Shadow確認画面

`/ui/shadow`は、承認済みPilot倉庫在庫と確定済みPOINT予測を使い、
Phase 3T-Aのgross在庫見通しと3T-BのFEFO試算を**参考値として表示する読み取り専用画面**である。
画面上部・日別詳細へ`SHADOW`と「出荷指示ではありません」を明示する。

## 操作

1. `/ui/shadow`を開き、接続コードまたは設定済みIdPでログインする。
2. 管理者が確認済みのPilot scope版、商品・倉庫対応版、予測run IDを入力する。
3. 計算時点、最低残存日数、注意日数、確認者・理由・確認日時を入力する。日数に未確認の仮値を使わない。
4. 「参考値を表示」を押す。対象JAN×倉庫ごとの現在庫、7日・14日需要、不足見込み、期限内未消化見込みが一覧になる。
5. 「見る」で日別の予測需要、gross残高、FEFO使用可能残高、未充足、期限内未消化を確認する。「計算に使った版と時刻」で根拠を確認する。

APIは`POST /api/field-shadow/preview`。既存の`READ`権限を要求し、snapshot・scope・bridge・run・policyを時点条件で検証する。
未承認在庫、欠測POINT、対象外JAN、期限不明、未確定policyは計算を停止する。
画面の入力値と結果はこの操作でDBへ保存しない。tokenも画面のメモリ内だけで保持する。

## 出力の限界

`gross残高`は入庫や期限消化を含まない仮想残高で、負値になり得る。
`FEFO使用可能残高`は賞味期限順に予測需要を消化した後の残高。
期限内未消化は予測に基づくリスクであり、確定廃棄量ではない。
工場在庫・生産予定・輸送時間・安全在庫は未反映。

**参考補充量とreference caseは生成しない。** 既存のFeedback Ledgerでは参考補充量が必須だが、
その算出policyが未確定のため、0や推測値を入れてcaseを作らない。
担当者判断、後日実績との週次比較、正式なShipment Recommendationもこの画面には含めない。
補充量policy確定後にreference case自動生成と判断UIへ接続する。

この工程の試験は人工10商品×14日で行う。実データの業務受入や現場Shadow開始承認を意味しない。
