# pilot.55：2台で共通した起動確認エラーの修正

2026年10月29日 ／ Windows x64 ／ 0.6.0-pilot.55

## 2台のログから確定したこと

デスクトップ2回、ノート1回の起動で、すべてREADY_FileNotFoundErrorが記録されている。一方、api-server.logは全回でApplication startup completeと48150での待受を記録している。APIが起動しないのではなく、起動チェック側がファイル関連の例外で停止している。

pilot.54のプロキシ対策だけでは解消できなかった。今回の両端末のログはHTTP 403等ではなくFileNotFoundErrorであり、前回のプロキシ仮説を確定原因としては扱わない。pilot.54で追加した45秒の上限と診断ログは動作していた。

## 調査と再現

pilot.54のurllib.request.build_openerは、HTTP接続用でも既定のHTTPSHandlerを作る。そこでSSLの既定コンテキストが初期化され、Windowsの証明書ストア等の読込みを行う。ここでFileNotFoundErrorが起きると、127.0.0.1へのHTTP接続に進めない。配布EXE内のsslのバイトコードがビルド環境の実装と一致することも確認した。

TLS初期化とWindows証明書ストアの列挙にFileNotFoundErrorを発生させるテストで、旧版のopenerがHTTP接続前に同じ例外を出す経路を再現した。ただし、2台で実際に欠けているファイルや証明書ストアの名称は、提供ログに記録がなく未特定。この再現をもって現場PCの特定ファイルが欠けていると断定しない。

## pilot.55の変更

- 起動・制御のローカル通信を、127.0.0.1固定のhttp.client.HTTPConnectionへ変更。HTTPSHandler・SSLコンテキスト・プロキシの初期化を経由しない。
- 同じ共通関数を使う終了処理、管理者画面の探索、更新後の起動確認にも適用する。
- リダイレクトを追わず、Tokenを別の接続先へ転送しない。HTTP状態、応答上限、JSON形式の検査、接続のcloseを維持する。
- 通信デバッグ出力は0に固定。例外時は接続段階、数値のOSエラーコード、コードの位置を記録する。例外本文・欠落ファイルのパス・Token・HTTP応答本文は記録しない。
- 起動中画面、中止ボタン、全体約45秒の確認上限、同じ保存先の画面を開き直す機能は継続する。

AI・ログ送信・更新取得など外部HTTPSの証明書検証は無効化していない。今回の修正はアプリ内のHTTP制御接続が対象で、起動後の外部サービス疎通は別途確認する。

## 切替手順

1. pilot.54の起動処理を終了する。画面から終了できない場合は、作業を保存してPCを再起動し、旧版を再起動しない。
2. BunsenPortable-0.6.0-pilot.55.zipを別の新しいフォルダーへすべて展開する。
3. データを引き継ぐ場合は、旧版が完全に終了した状態で、旧Data全体を新版の空のDataへコピーする。元フォルダーは保管する。空の新版Dataを旧Dataへコピーしない。
4. 新版の「ブンセン予測を起動.cmd」を開き、起動中画面から通常ランチャーとブラウザーへ進むか確認する。画面の版番号が0.6.0-pilot.55であることも確認する。
5. 履歴・API保存状態を確認する。同じPC・同じWindowsユーザーの引継ぎを前提とし、別PCではAPIキーや送信用Tokenの再設定が必要な場合がある。

## もし再発した場合

pilot.55のData/Logsにあるlauncher.log、api-server.log、api.logをまとめて提出する。新版のlauncher.logには、reasonに加えてdiagnosticが残る。HTTP_INIT／HTTP_REQUEST／HTTP_RESPONSE／HTTP_BODY／JSON_RESPONSE、errno、winerror、関数名・行番号で、ファイル参照が失敗した処理を確認できる。TokenやAPIキーの文字列を提出しない。

## 検証

起動・制御を含む関連テスト139件成功、2件除外、105.85秒。起動モジュールは28ケース。通常の取込・予測、欠損確認、保存済み結果、バックアップ復元、ログ送信、更新、管理者認証を含む。全体回帰スイートは今回再実行していない。

TLS初期化が失敗する条件を維持したまま、実際のcreate_appのready・認証付きcontrol/status・drainを、HTTP接続アダプターとTestClientで通した。サーバーやネイティブ画面を新たに起動せず、実API契約を確認した。HTTPエラー・異常応答・リダイレクト・接続終了、診断ログの秘密情報不在も検査した。

除外2件は、以前の自動承認レビューで起動を拒否された実サーバー試験。回避して実行していない。凍結EXEと今回の2台での実起動は未検証。Starlette/httpxの非推奨警告1件が残る。配布物は凍結コードと画面資材の一致、全ファイルSHA-256、ZIP CRC、空Dataと秘密情報不在を検証する。
