# Phase 3S-7 JAN mapping確認支援結果

## ゴール

Phase 3S-6で最大の阻害要因となった商品コード→JAN mappingを、担当者が確認できる候補CSVへ変換する。候補を自動承認せず、正式mapping保存には全商品の人手確認を必須とする。

## 実装内容

- 出荷の商品コード→JANを優先し、コードが空欄の場合は商品名と有効JANの関係を全出荷CSVから収集する候補生成moduleを追加した。
- 在庫の商品コードが持つ名称variantをすべて使い、一意、複数候補、候補なしへ分類する。
- 一意候補はJANを確認用CSVへ事前記入し、コード一致または商品名一致の根拠と`要確認`をメモに示す。
- 複数候補はJAN欄を空欄のまま保ち、候補値を確認メモへ提示する。
- 候補なしはJAN欄を空欄のまま保つ。
- 正式保存には全行の確認メモが完全に`確認済み`であることを要求する。
- 未確認件数をAPIと担当者画面へ表示する。

商品名一致は候補生成にだけ使う。商品名の変更、表記揺れ、同名別商品があるため、商品コード→JANの業務判断には使わない。

## 文字コード境界BUG

既存の一部CSV読取は固定byte数で文字コードを判定し、末尾がCP932文字の途中になるとファイルを読み飛ばしていた。完全なCSV行を単位として判定する共通関数へ分離し、商品候補、在庫mapping分析、在庫preview、在庫正規化で再利用した。読めないファイルは候補生成時に黙って除外せずエラーとする。

## 実データ確認

実データをRepositoryへ保存せず、集計値だけを確認した。

| 項目 | 結果 |
|---|---:|
| 出荷CSV | 1,943 |
| 在庫CSV | 1,926 |
| 在庫商品コード | 147 |
| 一意候補 | 130 |
| 複数JAN候補 | 15 |
| 候補なし | 2 |

Phase 3S-6のPreflight結果と一致した。

## 安全性

- 実CSV、商品名、商品コード、JAN候補をcommitしていない。
- 候補CSVは利用者へのdownload responseとしてだけ生成する。
- 候補JANが入っていても`確認済み`へ変更されるまでmappingを保存しない。
- 複数候補からシステムがJANを選択しない。

## 残タスク

1. 担当者が130件の一意候補を確認する。
2. 15件の複数候補を商品マスター等で解決する。
3. 2件の候補なし商品へJANを補う。
4. 全147件を`確認済み`として保存し、Phase 3Sの`ProductMappingRecord`へ接続する。
5. 正式mapping versionでPhase 3S-6 Strict Validationを再実行する。
