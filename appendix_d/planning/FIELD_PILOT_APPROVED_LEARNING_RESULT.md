# Field Pilot 承認型学習と「今日やること」画面 結果

日付: 2026-09-28 JST  
対象: Windows現場PC / Field Pilot / SHADOW・READ ONLY

## 実装した範囲

- Unified InboxでUNKNOWNまたはREVIEW_REQUIREDとなったCSVから、header、fingerprint、encoding、日付・JAN・拠点・数量・賞味期限の列候補、先頭100行の型だけをLearning Candidateとして記録する。原本行の値は学習台帳へ複製しない。PDFは従来どおり人間確認待ちで、抽出値を正式採用しない。
- 既存ルールに対する非重要列の追加は、列条件と原本全行の値を検査した後、担当者の「この内容で覚える」で認識契約を有効化できる。数量・単位・JAN・賞味期限・拠点などの重要変更、新しい種類、判断困難な候補は管理者へ送る。担当者の「違う」も履歴に残す。
- 管理画面で種類、拠点、日付、数量、JAN、賞味期限、原本単位とCASE単位を確認し、原本全行の形を検証して承認または却下する。契約は版付きで保存し、無効化・再承認では旧版を保持したまま新しい版を作る。承認者、時刻、前後の状態を追記型の履歴に残す。
- 承認済みの形式は同じheaderの次回入力で自動認識する。学習済み形式でも分類後はRECEIVEDであり、正式取込のVALIDには昇格しない。必須入力がVALIDでない日は既存のShadow結果を表示しない。
- 通常画面に「今日やること」の3段階、短い不足表示、新形式の確認、完了条件を追加した。技術IDの表示は通常画面から除いた。管理者画面は別経路に置き、現場PC内からの管理tokenを必要とする。
- Windows Installerで管理tokenと担当者IDをローカル設定に追加する。既存データと学習台帳はコード版更新後も保持する。

## 検証と制限

人工CSVでは、未知候補、任意列追加、担当者承認、同一形式の自動認識、重要変更の管理者待ち、100行以降の異常値停止、二重承認、無効化後の再承認とPC再起動相当の台帳再読込を検証した。APIでは管理token、Origin、既存の在庫・出荷変更POST禁止を確認した。Windows実機での再インストール・画面操作と実データの一連確認は未実施である。

追加の[実データ学習検証](FIELD_PILOT_REAL_DATA_LEARNING_VALIDATION_2026-09-28.md)で、提供済み3,869 CSVを分類し、全件の候補生成と代表3形式の一時Inbox投入を確認した。倉庫在庫の159/160列上限と列意味の誤提示を修正した。正式取込から予測更新までの実データ一連確認は引き続き未実施である。

**正式取込と予測更新は未接続。** 現場のCSVについて日次必須集合、商品・拠点mapping、CASE数量、正式snapshot日時、出荷・在庫の取込契約が未確定である。Unified Inboxの正式取込callbackは存在するが、Field Pilot起動経路には実装を接続していない。したがって今回の分類・承認だけでInventory Snapshot、Forecast Run、14日Projection、FEFO Shadowを自動更新することはない。画面の「本日の確認は完了しました」も、既存の正式データとShadow結果がともにREADYになる場合以外は表示しない。

学習候補の原本全行検証は、日付・非負数量・固定拠点などの**構造検証**である。JANの業務上の正しさ、商品対応、賞味期限の意味、数量照合、正式mapping、既存在庫SnapshotのAPPROVED判断を代替しない。

管理用tokenは同じPCの`pilot.env`に保存する。専用管理画面とHTTP操作の誤操作防止にはなるが、同じWindows利用者が設定ファイルを読める環境では権限分離の証明にはならない。管理者・担当者を強く分離する現場運用にはWindowsアカウント分離または外部認証が必要である。

## 次に必要な作業

1. 管理担当者が実CSVのschemaと日次必須集合を承認し、商品・location・CASE・snapshot日時の正式mappingを登録する。実データはRepositoryへ入れない。
2. 種類別の正式取込callbackを接続し、Validation、Reconciliation、重複・訂正、失敗時停止を実データで検証する。PDFは抽出・原本照合・人間確認adapterを別に実装する。
3. 正式取込成功後だけForecast更新、14日Warehouse Projection、FEFO Shadowを順番に起動し、部分失敗と安全な再実行を検証する。
4. 現場PCで新しい配布ZIPの導入、コピー途中、再起動、管理者操作、画面の3段階、全必須充足、結果照合を実施してGO判定する。
