# 予測数量編集制御・精度検証 実装報告

対象：bunsendev/kiban / Portable pilot.44、2026-10-20。

## 1. 既存調査
[調査・管理・移行方針](FORECAST_ACTUAL_VERIFICATION_PLAN.md)を参照。
日別予測と担当者修正、および期間合計の判断は既に別保存だった。一方、日付による更新制限、実績確定との突合、日別精度の専用画面はなかった。元予測はRun結果・hash付き日次build・Production Runに残る。Productionの古い完了時刻はDB初期化で補完された可能性があり、現在の値から真の作成日時を復元しない。

## 2. 変更した処理
- forecast_verification.py：元予測の追記保存、正式取込済み実績、実績の競合、締め時刻policy、日別照合・指標。
- formal_forecast_pipeline.py：JAN/倉庫対応とゼロpolicyの確認を経た日次取込のOBSERVED/CONFIRMED_ZEROだけ確定。MISSING/不正を除外。予測計算前に取込済み実績を登録し、履歴不足で予測対象がなくても実績を保持。
- production_handoff.py / app.py / reference_demand.py：種類を分けて元予測と作成時点・学習期間・モデルを保存。参考需要や単位不明の簡易Runを正式CASE実績と無条件に比較しない。
- result_feedback.py / result_feedback_routes.py：日別数量の更新制限・認証済み例外・変更前後監査。CSVでは未修正の確認後数量を未設定にする。
- field_store.py / field_read_model.py / field_routes.py：期間の開始日を基準に同じ制限を適用。過去の修正を「確認/保留」操作で解除する迂回も禁止。日別への自動配賦なし。
- verification_routes.py / accuracy.html,js,css：比較履歴・期間選択、元予測/担当者修正/実績、確定状態、誤差、商品別・日別指標、管理者用締め時刻・例外修正。
- operator-results.js / field/review.js / field/index.html：変更禁止の説明と入力無効化、比較画面への導線。日常4ステップの構成は維持。
- 文書・ビルド同梱ガイド・APP_VERSION・関連テストを更新。

## 3. DBと移行
Data/State/forecast-verification.sqlite3を追加。forecast_versions、actual_imports、actual_values、edit_policiesの4テーブル。予測sourceは一意・上書き不可。実績は取込単位の追記で異なる数量を競合扱いとし、勝手に最新を選ばない。
既存result-feedback.sqlite3とfield-ui.sqlite3はJSON履歴へ例外修正・変更前数量・判定policyを追記する。既存履歴の書換えや削除、実績から確認後数量への転記はしない。更新前Dataを終了状態でバックアップし、戻す場合はそのバックアップへ復帰する。

## 4. 編集制御・例外
ユーザー確認済み：実績ファイルの取込時点で確定（2026-10-20）。ここで取込とは正式な行の採用であり、PDF抽出候補やZIPの受付のみではない。
未来日は理由を付けて修正可。過去日は確定済み/未確定を別表示して通常数量変更を禁止。当日は実績確定済みなら禁止。未確定では日本時間の締め前のみ可、締め時刻未設定なら保留。締め時刻はまだ業務指定されていない。
Windows管理者が既存の設定起動から発行する15分セッションを認証し、理由必須で例外修正を許可する。自己申告のroleやexceptionalだけでは許可しない。日別は専用管理者欄、期間合計は同じ認証を使用するreview APIをIT担当者が使用できる。修正者は入力名であり、企業IdPによる個人認証ではない。
実績台帳の書込みロックを保持して数量変更を再判定し、同時取込による確定後のすり抜けを防ぐ。入力型不正は422、未認証例外は403、履歴版競合は409。

## 5. 指標
誤差=実績−元予測。誤差率=誤差/元予測×100（元予測0では算出不可）。平均誤差、MAE、WAPE=絶対誤差合計/実績合計×100（実績合計0は算出不可）。Runを選んで期間・商品別・日別を表示。担当者修正は参考列のみで指標を変えない。件数と除外理由を明示し、評価可能データ0件では評価不能と表示する。少数件数から実用精度を保証しない。

## 6. 過去履歴の利用範囲
新しい収録を備えたpilot.44で保存した履歴が確実な評価対象。古いProduction Runは値を保持しても作成日時不明として集計対象外。単位・範囲不明も対象外。旧日次manifestや既存簡易Runに保存情報があっても、全既存履歴の自動移行・対応確定は行わない。再予測は別のRun/sourceまたは参考需要requestとして保持し、元を実績で置き換えない。対象日以降に作成した過去向け参考予測は事前予測の精度に含めない。
