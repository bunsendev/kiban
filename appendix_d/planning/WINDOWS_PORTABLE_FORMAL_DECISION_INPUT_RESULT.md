# Windows Portable 正式Decision入力・自動試算 実装結果

## 目的

担当者が手順8の日次業務サマリーを作成した後、工場在庫、生産予定、工場から倉庫へのroute、安全在庫を正式CSVで確認し、正常な入力だけを手順9の到着時点在庫・推奨出荷試算へ接続する。入力不足や異常値を0で補わず、担当者が修正できる形で残す。

## 操作手順

1. Windows Portable担当者画面で手順8まで完了する。
2. 手順9の「入力テンプレートZIPを保存」を押す。
3. ZIP内の4ファイルへ確認済みの値を入力する。
   - `factory_inventory.csv`: 工場在庫。必須。
   - `production_plans.csv`: 生産予定。予定がない場合は見出し行だけでよい。
   - `routes.csv`: 工場・倉庫間の最短、標準、最長時間と今回の採用基準。必須。
   - `safety_stock.csv`: 倉庫別の安全在庫日数とCASE出荷単位。必須。
4. ZIP直下のファイル構成を変えずに保存する。
5. 確認者、確認理由、ZIPを指定し、確認欄を選んで「正式入力を検証して試算」を押す。
6. 採用行数と「採用しなかった行・不足入力」を確認する。必須入力がある場合、正常行だけでSHADOW試算が続き、確認が必要な項目は結果のblockerにも残る。

## 実装した契約

- CSVはUTF-8、列名と列順はテンプレートとの完全一致を要求する。
- 数量はDecimalのCASEとして扱い、空欄・不正値・負数等を0へ変換しない。
- 日時はtimezone付きISO形式を要求する。
- routeは既存Phase 3Sの`RouteLeadTimePolicy`、工場在庫・生産予定・安全在庫は既存Decision Engine契約で検証する。
- 異常行はファイル名、行番号、原値を含まない行SHA-256、固定理由、検証メッセージを隔離記録に残す。
- 日次対象にないJAN・倉庫、route・安全在庫・工場在庫の不足、工場在庫と結び付かない生産予定を別の確認事項として残す。
- 入力ZIP原本、日次サマリーSHA、build ID、確認者、確認理由から決定的package IDを作る。同じ入力は同じ結果へ収束する。
- 原本ZIPと正規化packageをローカルに不変保存し、読み出し時に両方のSHA-256を再検証する。
- packageは作成元の日次サマリーだけで利用でき、別buildや別サマリーへの流用を拒否する。
- 既存の個別手入力は互換・検証用として折り畳んで残した。

## 制限と運用上の位置付け

- 結果はSHADOW参考値であり、正式な出荷指示ではない。
- 正常行だけの部分試算を許可するため、`PARTIAL`時は確認事項と計算対象外理由を必ず確認する。
- 生産予定ファイルは任意だが、架空の予定を生成しない。
- 現場で確認された正式工場コード、route、CASE換算、安全在庫policyの実値はRepositoryへ保存しない。
- PDFはこの契約へ直接入れず、抽出、validation、人間確認を終えた構造化データを同じCSV境界へ渡す。

## テスト範囲

- 4つのCSVの正常化、異常行の隔離、重複・未知・階層化ファイルの拒否。
- 日次対象に対する不足・対象外入力の分類。
- 2倉庫のテンプレート生成、package登録、冪等再送、packageからDecision Engineへの自動接続。
- packageまたは原本ZIP改変時の拒否。
- 既存の個別入力APIとDecision Engineの回帰。

実データと認証情報はRepositoryへcommitしていない。
