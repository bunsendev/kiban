# 現場担当者の結果確認・修正・フィードバック

対象版: 0.6.0-pilot.4

## 現場で行う操作

ファイルアップロード → 内容の確認・不足情報の判断 → 予測 → 結果確認・修正・フィードバック。
フォルダ投入は折りたたみ表示にし、開発用のモデル比較・設定変更・監査操作は現場画面に表示しない。
IT確認端末も同じ画面を使用する。既存の端末識別と独立データを維持する。

- 商品・倉庫ID検索、30日別結果ごとのページ切替、商品・倉庫単位の選択。
- 全件CSV、選択商品・倉庫の全予測日のCSV。検索は表示フィルターであり、全件CSVの対象を変えない。
- 日別数量の修正、予測の評価（妥当／多い／少ない／判断できない）、理由・コメント・担当者を保存。
- 元の予測値を保持し、確認後数量と併記。修正数量0と空欄を区別。空欄で元の予測へ戻せる。
- 修正・評価は追記履歴。別タブからの同時変更は409で拒否し、再表示を促す。
- 予測完了後は入力確認を折りたたむ。過去の分析から結果とフィードバックを復元する。

## 保存とモジュール境界

`portable/api/result_feedback.py` はSQLite追記台帳とCSV生成、
`result_feedback_routes.py` はHTTP境界、`static/operator-results.js` は結果操作を担当する。
既存Workerの予測をサーバーで取得し、クライアントから元の予測値を採用しない。
正式WorkerのDecimal値を既存HTTP契約と同じ数値表現に変換して保存する。

新規保存先は `Data/State/result-feedback.sqlite3`。既存DBは変更しない。
元の予測、担当者修正、端末設定、アプリ版、保存日時を保持する。
CSVには最新の数量・評価・コメントを含み、Excelの数式として解釈され得る文字列を無害化する。
予測モデルへの自動学習、正式在庫変更、出荷指示、開発者への自動送信は今回の機能に含めない。

## 検証

- Portable回帰51 passed。正式Workerの140日別結果、選択1系列14日分のCSV、再起動後の修正復元と原本保持を検証。
- Ruff全体成功。JavaScript結合構文検査をPortable回帰に含む。
- ブラウザーで人工データの結果表示、検索、1→3の数量修正、理由・評価・コメント保存を確認。
- ブラウザーで実際に保存されたCSVを読み、全件140行／10系列、選択14行／1系列、元の値1と修正値3を確認。
- テスト用人工データは一時領域に隔離。実データ・担当者情報をリポジトリへ含めない。

## 既存の制限

予測対象は既存Pilotの倉庫ごと最大20商品。この変更は対象上限を拡大しない。
商品名ではなくJANを含む商品・倉庫IDで検索する。表示する日別予測は出荷指示ではない。
現場PCの実機受入、実業務データの精度確認は別途必要。
