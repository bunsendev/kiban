# Windows Portable 推奨出荷・担当者判断 実装結果

## 目的

正式Decision入力から作成したSHADOW試算を、現場担当者が商品・倉庫ごとに確認する。推奨どおり採用、増量、減量、見送り、本日は出荷しない、という判断を追記型で保存し、現場判断を失わず次回の設定改善へ利用できる状態にする。

## 操作手順

1. 担当者画面の手順9で正式入力ZIPを検証し、推奨出荷量を試算する。
2. 試算表の対象行にある「判断を入力」を押す。
3. 確認者と判断を入力する。増量・減量時は判断後数量を、増減・見送り時は固定理由を入力する。
4. `OTHER`を選んだ場合は補足を入力する。
5. SHADOW参考値の確認結果であることを選び、「判断を保存」を押す。
6. 判断履歴と設定改善候補を確認する。改善候補は予測モデルやpolicyへ自動反映されない。

## 保存契約

- 試算結果SHA-256、JAN、倉庫、推奨数量、判断後数量、差分、固定理由、補足、確認者、時刻を保存する。
- 判断は商品・倉庫単位のrevisionとして追記し、過去判断を更新・削除しない。
- 古いrevisionからの保存を409で拒否し、画面更新を要求する。同じ内容の再送は同じ判断へ収束する。
- `REJECTED`の数量は欠測、`NO_ACTION`の数量は確定ゼロとして保持し、両者を混同しない。
- 保存内容はSHA-256で検証し、DB内の数量や理由が変更された場合は読み出しを拒否する。

## 設定改善候補

最新判断のうち増量・減量・見送りだけを、判断種別と固定理由ごとに集計する。件数、平均数量差、対象JAN・倉庫を表示する。担当者判断だけで安全在庫、lead time、出荷単位、予測モデルを自動変更しない。正式なpolicy変更には別の確認・版発行・受入試験が必要である。

## API

- `GET /api/formal-forecast/{build_id}/daily-summary/{summary_key}/shipment-recommendation/{request_key}/review`
- `POST /api/formal-forecast/{build_id}/daily-summary/{summary_key}/shipment-recommendation/{request_key}/review`

## 制限

- 現段階はSHADOW参考値の確認台帳であり、正式な出荷指示を発行しない。
- 後日実績との比較、policy変更案の承認、正式policy版の発行は次工程である。
- 実データ、実担当者名、認証情報はRepositoryへ保存していない。

## 検証

- 採用、増量、減量、見送り、確定ゼロの数量規則。
- 固定理由と`OTHER`補足の必須条件。
- 冪等再送、revision競合、未知の商品・倉庫、SHADOW未確認の拒否。
- 判断履歴の改変検知と設定改善候補集計。
- 2倉庫20行の正式入力から試算、担当者判断保存、再取得までのPortable API結合。
