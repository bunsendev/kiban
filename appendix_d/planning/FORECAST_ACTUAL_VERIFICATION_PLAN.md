# 予測・担当者修正・実績の分離（2026-10-20）

## 既存調査
- result_feedback.py / result_feedback_routes.py：日別予測yhatと担当者quantityを別保存。追記履歴と競合検出あり。日付・実績確定による制限なし。CSVの確認後数量は未修正時も元予測を表示する。
- field_store.py / field_read_model.py：現場4ステップは期間合計の別判断台帳。日別修正への自動配賦はない。期間と日別の両経路を制限する必要あり。
- store.py：単純Runの開始・終了時刻、原本/結果hashあり。formal_forecast_pipeline.py：日次build、学習期間、作成日時、元予測、daily.csvを保存。production_handoff.pyは別Runの予測。reference_demand.pyは参考需要のみ。これらの意味を混ぜない。
- input_history.pyは原本と候補履歴であり実績確定フラグではない。正式日次CSVはOBSERVED/CONFIRMED_ZERO/MISSING/PARTIAL_OR_INVALIDを持つ。
- ローカル版はlocalhost制限。通常操作のactorは入力値であり認証済み役割ではない。例外修正に自由入力のadminフラグを使用しない。既存Windows管理者発行の15分セッションを再利用する。

## 確認済み方針
利用者は2026-10-20に「実績ファイルの取込時点で確定」を選択。正式取込で商品・倉庫・単位が解決した行を確定し、候補・隔離・欠測は対象外。PDF抽出だけでは確定しない。異なる確定値の再取込は競合として評価対象外にする。
過去日の数量変更は実績確定/未確定を区別して通常操作を禁止。当日は締め時刻未設定なら保留、設定前は未来日と同じ扱いをしない。締め時刻は管理者が設定する。
期間合計は開始日が当日以前なら通常数量変更不可。過去部分を未来日に勝手に配賦しない。評価・感想の記録は数量変更と分離する。

## 保存・移行
新しいSQLite検証台帳を追加。原本・既存予測・既存修正履歴は変更しない。新規予測の作成時刻と学習期間を記録。既存の履歴を推測して生成しない。予測作成日時が対象日以降の参考バックテストは将来予測の精度集計に含めない。
既存Data全体を終了状態でバックアップ。追加台帳は旧台帳と独立。ロールバックは更新前バックアップへの復帰であり、更新後データを旧版へ流用しない。

## 評価
元予測と確定実績を同じ商品・倉庫・日付・単位で比較。修正値は参考列。誤差=実績−元予測、誤差率=誤差/元予測（元予測0では算出不可）、MAE=絶対誤差平均、WAPE=絶対誤差合計/実績絶対値合計（分母0では算出不可）。指定Runごとに評価し、複数Runを黙って混合しない。欠測・未確定・競合・対応不明・履歴なし・後知恵を理由付きで除外する。
