# 学習データのバックアップ・再インストール後の復元

2026-10-20。既存の更新時バックアップはアプリ停止中にDataをZIP化するが、担当者が画面で保存・検証・復元する経路はなかった。保存済み学習データを新しい設置先でも復元する経路を追加した。

## 実装

- `portable/runtime/learning_backup.py`：ファイル一覧とSHA-256付きZIP、SQLite Backup APIによるWAL対応バックアップ、検証、次回起動時の復元、フォルダ置換ジャーナル、退避・中断復旧。復元候補に対するアプリ初期化検査（監視・送信の起動なし）を切替前に実施。
- `portable/api/learning_backup_routes.py`：保存、検証、復元予約、取消、結果参照。既存のlocalhost・Origin制限を継承。
- `/learning-backup`：担当者画面・従来画面の設定欄・ログ提出/更新欄から開く。保存・予約・取消には完了ダイアログを表示。
- `create_app`はDBや監視処理を開く前に復元予約を処理する。復元予約後の変更要求を拒否し、投入監視も受付を止める。

処理中の取込・分析・設定変更があれば409で待機を案内する。バックアップ中の新しい変更要求を止め、通常ファイルの途中変更・増減を検出する。SQLiteは本体ファイルだけをコピーせずBackup APIを使う。WAL・SHMを復元ZIPへ混ぜない。

## 保全と境界

復元はマージではなくバックアップ時点への置換。退避・予約はData外の `BunsenRecovery-<識別値>` に保持し、現行Dataを退避してから検証済みDataへ切り替える。元Dataの移動後に置換失敗なら元へ戻す。電源断等の次回起動では、置換未完了を検出し元Dataへ戻す。ランチャーが空のDataを先に作り直した場合も検出する。

除外設定・確認修正・JAN対応・履歴比較等のDataを対象にする。端末ID、送信設定、未送信キューは復元先のものを保持する。APIキー・TokenのDPAPI保管領域はData外であり、このZIPへ入れない。Data内のDPAPI、管理者セッションも除外する。

新形式はmanifest・ハッシュ・CRC、旧形式は明示確認の上でCRCを検証。DBのquick_checkはバックアップ作成時と復元の展開後に実施する。パス逸脱、Windows予約名、重複名、ZIP内リンク、暗号化、新しい版、容量超過を拒否。署名による提供元認証は行わないため、自分で保管したバックアップを選ぶ。

外部DB・資格情報・外部パス先ファイルは対象外。再設置先が変わる場合も学習設定・履歴ファイルは復元するが、既存の署名/ハッシュ付き成果物や正式Run内の外部URIを自動書換えしない。外部接続と古いRunの再開は別途確認が必要。
