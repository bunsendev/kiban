# Portable ログ提出・更新（pilot.14）

## 現場操作

`/field` の開始画面に「ログ提出・アップデート」を追加する。
IT担当者が端末ごとにHTTPS送信先、登録済み端末ID、Token、受信RSA公開鍵を入力し、同意して有効化する。
TokenはWindowsユーザーのDPAPIで保護し、配布ZIPと業務Dataには平文保存しない。
OpenAI APIキーとは別の資格情報である。既定の候補URLは従来の共有サーバーだが、初期状態は送信停止。

- 起動時：未送信の再送と新しい記録の送信、GitHub更新確認をバックグラウンド実行。
- 終了時：ランチャーの「終了（ログ送信）」または閉じる操作で送信。待機は最大60秒。未送信は次回へ残す。
- ブラウザーだけ閉じた場合、PCの強制終了時は終了時送信を保証しない。保存済み記録は次回に回収する。
- 「今すぐログを送信」でも提出できる。成功ACKのみを送信済みにする。
- 「接続をテスト」は業務データを含まない暗号化テストを送る。
- 未送信数、要確認数、最終成功時刻、更新状態を表示する。

## 送信内容・互換性

通常は操作イベント件数、処理成功・失敗・中断件数、判断の採用・変更・保留件数、意見件数、アプリ版。
元ファイル、商品名、JAN、数量、APIキー、担当者名、ファイルパス、ログ全文は送らない。
「困ったこと」の自由記述は別チェックで許可した場合のみ送る。自由記述に秘密情報を記入しないことを画面に表示する。
AES-GCMと受信者RSA（3072bit以上）で暗号化し、HTTPSで既存SharedServerTransportへ送る。
送信先や同意内容を変更すると、旧条件の未送信パッケージは隔離する。

外側は既存 `bunsen-feedback-v1` envelope、内側は `category=PORTABLE_FEEDBACK`、
`payload.format=bunsen-portable-feedback-v1`。payloadは application_version/counts/comments/
contains_raw_files/contains_raw_logs を持つ。既存 `decrypt_package` で管理側が復号できる。
PHP保管先専用であり、旧中央FastAPIの業務パッケージ検証契約とは同一ではない。
受信側の端末登録・Privacyヘッダー許可・保存後の復号確認は実接続受入で確認する。
Privacyヘッダーは同意条件のSHA-256先頭32桁、request_idは端末・同意版・収集カーソルのhash。
実サーバーへの送信成功は未確認。Tokenや受信公開鍵を推測・流用しない。

## 更新

配布元は `bunsendev/kiban-releases` に固定。起動時に確認するが、自動で置換しない。
「更新を確認」→作業保存チェック→「アップデートする」で適用する。
ランチャー経由の凍結EXEのみ適用可。直接 `--server` やソース起動では案内を表示する。
業務処理中は適用しない。適用決定後は新しい書込みを停止し、別プロセスが旧アプリ終了を待つ。
同梱Ed25519公開鍵による署名、配布URL、ZIPのhash/サイズ、内部全ファイルhashを検証する。
Data全体を検証付きZIPバックアップし、コピーDataで起動試験、App置換、実Dataで起動試験を行う。
通常の処理例外では旧AppとDataへ復元し、結果を次回画面にも保持する。
更新用ZIPにData/Updates、パストラバーサル、リンク、Windows予約名は許可しない。
DBの破壊的migrationを伴う更新は今回受け付けない（database_migration=0）。
停電・ディスク故障・強制終了をまたぐ完全なトランザクション保証はない。Updates配下のバックアップは保持し、削除はしない。

## 配布担当者の署名・公開

1. 新しい版で配布ZIPをビルドし、検証する。
2. `python -m portable.sign_release <ZIP> --private-key <暗号化済み秘密鍵> --minimum-version 0.6.0-pilot.14 --output <新しい署名出力フォルダ>`。
   パスフレーズはローカル端末で非表示入力する。チャットや引数・ログへ書かない。
3. `kiban-releases` の `portable-v<版番号>` リリースに、ZIP、portable-manifest.json、portable-manifest.sigの3ファイルを添付する。
4. 一台で更新確認→適用→旧データ・判断履歴・ログ送信状態の保持を確認してから現場へ案内する。

pilot.13以前にはこの更新入口がないため、pilot.14への初回切替は手動配布する。
署名秘密鍵のパスフレーズを必要とする実リリース公開は、担当者による署名後の別手順。
署名鍵は既存の公開鍵を再利用した。秘密鍵は本実装で読み取っていない。

## 検証

人工データと模擬HTTPで暗号化、重複防止、再送、同意停止、同意変更時隔離、
署名改ざん・hash不一致・危険ZIPの拒否、バックアップ、実Data起動失敗時の復元、
外部Origin拒否、ランチャー必須、更新中の書込み停止を検証する。
実サーバー受信・署名済み公開Releaseからの更新と現場PCでの実行は別途受入が必要。
