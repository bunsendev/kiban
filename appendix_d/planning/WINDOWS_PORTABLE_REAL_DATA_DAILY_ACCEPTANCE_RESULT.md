# Windows Portable 実データ日次Decision受入結果

判定日: 2026-10-05。対象はRepository外の提供済み在庫・出荷ZIPであり、原本と
生成データをRepositoryへ追加していない。

## 実行結果

| 段階 | 結果 |
| --- | --- |
| 原本分析 | 出荷3,907,441行、在庫200,917行を再分析 |
| 担当者確認対象 | 14項目・124行。賞味期限欠損77行を確認、12桁JAN45行と不正在庫2行を対象外として追記 |
| 正式在庫 | 神戸・加須の各10商品を既存Workerで登録、隔離0、数量照合一致 |
| 14日予測 | 加須10系列が対象。神戸10系列は在庫日と出荷基準日の不一致で安全停止 |
| Production予測 | 加須10系列で完了 |
| 日次サマリー | 1倉庫・10商品で作成 |
| Decision入力 | 工場在庫10行、route 1行、安全在庫・出荷単位1行が必要と判定 |
| 不足入力の送信 | 422で拒否し、空欄・不足値を0補完しないことを確認 |

このデータは過去時点の技術受入である。最新の工場在庫、正式route、安全在庫、
出荷単位が提供されていないため、実データを使った推奨出荷量は生成していない。
予測可能な系列だけを継続し、基準日不一致系列とDecision入力不足を理由付きで停止する
挙動が受入結果である。

## 今回の改善

- Decision入力待ちで対象倉庫数、対象JAN数、必要工場在庫行数を取得できるAPIを追加した。
- 担当者が画面へ確認済み値を入力し、既存の正式4 CSV ZIP契約へ変換できるようにした。
- 工場在庫は対象JAN全件を要求し、欠落・重複・対象外JANを正式package作成前に拒否する。
- 生成したZIPも原本SHA-256、行検証、隔離、内容アドレス保存を通し、再起動後も同じ
  日次実行から再開できる。
- 複数工場、倉庫別route、生産予定は従来の正式ZIP入力を維持した。

## 次の現場確認

担当者が最新業務日の工場在庫と正式policyを画面へ入力し、SHADOW推奨出荷まで進める。
値が未確定の場合は推測値を入れず、画面に表示される不足件数を業務確認リストとして扱う。
