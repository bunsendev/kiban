# pilot.54 起動画面が表示されない問題の調査と修正

2026年10月29日 ／ Windows x64 ／ 0.6.0-pilot.54

## 提供ログから確認できたこと

Logs.zipでは、14:05:47から14:23:21にかけて、内部APIが48150〜48180の全31ポートで順に起動している。最初の起動開始から約18分後、ランチャーがPORTABLE-START-001で終了した。APIが起動しないというより、ランチャー側の接続確認に通らない状態だった。

旧版は1ポートごとに35秒待ち、接続確認が失敗すると次のポートでも同じ処理を繰り返していた。ランチャー画面とブラウザーは接続確認に成功してから表示するため、その間は画面が出ない。再クリックの「起動済み」は、最初の起動処理が裏で待ち続けていたために出る。以前インストールしたことだけを理由に出るメッセージではない。

旧ログには接続失敗の詳細がないため、現場PCのプロキシが原因とまでは断定できない。ただし、旧コードのurllib既定通信がPCのプロキシ設定によって127.0.0.1もプロキシ経由にする経路を人工テストで再現した。修正版ではこの依存と長時間無画面の処理を改め、再発時に接続段階と失敗種別が分かるようにした。

## 修正内容

- アプリ内部の127.0.0.1通信は、専用の直接接続を使う。Windows・環境変数のプロキシを経由せず、リダイレクトも追従しない。起動確認・終了指示・管理者画面の探索・更新後の起動確認に共通適用する。
- 外部AI、ログ送信、更新取得の通信設定は従来どおり。制御Tokenは固定したローカル接続だけへ送り、ログに出さない。
- 起動確認前に「起動中」の画面と経過秒数・中止ボタンを表示する。接続確認の待機は全体で約45秒に制限する。終了処理に数秒かかる場合がある。
- 稼働中の子APIが接続確認に失敗しただけで、31ポートへ順に再起動する処理をやめる。子が先に終了した場合のポート再試行も全体の制限時間内に収める。
- タイムアウト・中止・Job登録失敗時は、今回起動した子だけを終了する。正常に起動した子は継続する。
- 起動済みの場合は、同じData保存先のAPIだけを確認し、その画面を開き直す。別の保存先・別端末の画面を勝手に開かない。
- ログに、接続ポート、READY／CONTROLの確認段階、HTTP状態または例外の種類、経過秒数、子の終了状態を残す。Token・プロキシ認証情報・HTTP応答本文は記録しない。

## 修正版への切替手順

1. pilot.53のフォルダーはそのまま保管する。起動処理が残っていて終了できない場合は、作業中のファイルを保存してPCを再起動する。
2. BunsenPortable-0.6.0-pilot.54.zipを新しいフォルダーへすべて展開する。旧版のAppへ部分的に混ぜない。
3. データを引き継ぐ場合は、旧アプリが終了した状態で、旧フォルダーのData全体を新版の空のDataへコピーする。空の新版Dataを旧Dataへコピーしない。元フォルダーは残す。
4. 新版の「ブンセン予測を起動.cmd」を開く。初回設定がなければ用途と端末名を入力する。「起動中」の画面を確認し、通常のランチャーとブラウザーが開くか確認する。
5. 画面の版番号が0.6.0-pilot.54であること、履歴とAPI保存状態を確認する。既存のpilot.53の欠損一覧・予測方式選択も利用できる。

同じPC・同じWindowsユーザーのData引継ぎを前提とする。別PCではAPIキーや送信用Tokenの再設定が必要になる場合がある。アプリのセキュリティ設定を解除する手順は追加していない。

## まだ起動できない場合

新版のData/Logsにあるlauncher.log、api-server.log、api.logをまとめて提出する。版番号と発生時刻も確認する。特にlauncher.logのapi_probe_failed、api_startup_timeout、api_startup_failedで、READY_HTTP_403、CONTROL_HTTP_403、READY_URLError、READY_NOT_CURRENT等の理由を確認できる。APIキーやTokenの文字列を提出しない。

関連テスト131件成功、2件除外、348.59秒。新しい起動テスト20ケースを含む。取込・通常予測・品質検証・保存済み結果・全Data復元・ログ送信・更新適用・管理者認証・配布構造を検査した。重複する成功件数は加算しない。

プロキシ経由になる旧経路と新しい直接接続、制御Tokenの送信先、リダイレクト拒否、応答サイズ・形式、全体待機上限、子プロセス終了、中止、起動済み保存先の照合、画面生成と接続確認の順序を検証した。HTTP・子プロセス・Tk画面はテスト内で代替し、新規のサーバーやネイティブ画面は起動していない。

除外2件は以前の自動承認レビューで起動が拒否された実サーバー起動テスト。回避して実行せず、プロセス内・模擬I/Oで検証した。凍結EXEと現場PCでの実起動は未検証。提供ログの31回起動を同じ現場PCで再現したとはしない。今回、全体回帰一式は再実行せず、変更に関係する範囲を検査した。Starlette/httpxの非推奨警告1件が残る。
