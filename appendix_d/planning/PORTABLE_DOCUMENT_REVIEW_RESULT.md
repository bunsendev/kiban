# Portable pilot.24 文書読取・確認の改善

2026-10-07。対象は既存のPDF・画像adapter。自動で正式在庫を採用する変更ではない。

## 変更内容

- 印刷在庫受払表のadapterを分離。PDF埋込文字のJAN、賞味期限、基準日と、現在欄のケース・バラを取得する。合計行と過去・入出庫欄は採用しない。対応形式以外はAI経路へ案内する。
- AIは1ページずつ処理する。印刷PDFの埋込文字も未信頼の補助情報として渡す。画像だけの手書きPDFには文字補完を行わない。
- 原本、読取版、読取失敗、確認内容をSQLiteに保存。成功済みページを再利用し、再読取は追加料金の明示された操作から行う。ページの置換で明細を重複させない。
- ケース・バラを別管理する。原本欄の意味を確認した後でのみ箱へ換算する。バラが空欄の場合はゼロとして扱わない。C入は換算候補であり、確認なしに採用しない。割り切れない換算は黙って丸めない。
- 読取未完了でも、確認した行だけを理由付きで採用できる。未読取部分は保留として残し、原本全体の読取完了に変更しない。手入力の明細追加、不明行の理由付き除外に対応。
- XLSXの選択シート・適用開始日ごとにJANマスター版を登録する。商品名・商品コード・JANコードの順の列が対象。左右に分かれた同形式の表も対応。数式セルは採用しない。マスターは外部AIへ送信しない。
- JAN候補は選択して原本と照合する。同一JANの異なる商品コードを保持し、旧シートと現行シートを混ぜない。適用日に適した版かを担当者が確認する。
- 確認した抽出版と採用範囲を判断履歴に固定。確認済み原本の再読取と、更新前の確認画面からの保存を拒否する。既存DBにはテーブルを追加するだけで、原本・承認を削除しない。

## 実データ検証

ユーザー提供の印刷PDF2件（各8ページ）、手書きスキャンPDF1件、JANマスターの指定シートを使用した。原本・抽出明細・マスターはRepository外のローカル検証領域へ保存し、commit・配布ZIPには含めない。

- 印刷PDF全ページのローカル読取で113行／43JAN、123行／52JANを取得。前回の原本調査の明細数と一致。初行のケース・バラ分離、基準日・賞味期限を照合した。
- マスターの指定シートは75明細を登録可能。無効JAN明細は0件。同一JANの別商品コードを保持できた。
- この件数一致は全数量・全倉庫の業務確認完了を意味しない。空欄、単位換算、マスターの適用日などは原本照合が必要。
- 保存済みキーを使い3原本の先頭ページでAI実読取を試したが、全件HTTP 401（認証失敗）。キー保存・DPAPI読込成功とAPI認証成功は別。キー・HTTP応答本文をログに出していない。有効なキーを画面で再保存した後のAI実読取・手書き精度確認は未完了。
- 実データを確認済みと偽って分析・予測へ渡していない。確認→CSV受渡し→既存分析の接続は人工データで検証した。

## テスト

Portable回帰134件合格。文書関連・キー保存・投入フォルダの最終確認37件合格。Ruff全体合格。Mock DOMでキー状態、原本登録、送信同意、認証失敗、部分確認画面、手入力、再読取入口を確認した。

追加テストは、ページ途中失敗・再開、失敗時の以前の結果保持、ページ置換、古い抽出版での確認拒否、部分採用の理由、手入力追加、バラ残数保存、空欄・NaN・不正換算拒否、マスター版の分離、同一JANの別SKU保持、数式非採用、PDFページ境界、合計行除外を対象にする。

現場PCの実ブラウザー・凍結EXEの起動は今回再実施していない。以前のプレビューサーバー起動が自動承認審査で拒否されたため、別手段の起動で回避せずTestClientとMock DOMで検証した。

## 現場での受入手順

1. アプリの小さい起動画面から終了し、pilot.24のプログラムを入れ替える。既存Dataを保持する。同梱HTMLマニュアルを参照。
2. 原本を文書取込欄へ登録。印刷在庫表はAPI不要の読取を選ぶ。対応しない形式はAI読取を選ぶ。
3. JANマスターのシートと適用開始日を登録し、当該データに合う版で候補を確認する。
4. 原本のページ・JAN・日付・倉庫・ケース・バラを照合する。原本に年や単位がない場合は現場の確認を記録して入力する。
5. 未読取部分を保留する場合は採用範囲を記入。不明明細は理由付きで除外。原本確認後に保存し、分析へ渡す。
6. 手書きは有効なAPIキーの再保存後に先頭ページで読取を確認する。キーをチャットや診断ログへ貼らない。候補商品・取消線・上書き・年・単位を重点確認する。

## 制限

1ファイル10 MB、PDF100ページ、抽出・確認明細1000行、マスター10000行・50列の上限がある。数量を自動推測しない。JANマスター照合は候補であり正式商品対応表の自動変更ではない。確認済み原本を訂正する新しい業務判断版の発行、複雑な帳票の汎用OCR精度保証は対象外。
