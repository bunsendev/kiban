        3. 確定済みデータで参考予測を検証

        未確認項目が残っていても、自動判定OKと担当者が確定した出荷データだけで実行します。

        在庫の内容を確認

        各倉庫の最新在庫だけを対象に、拠点・基準時刻・箱（CASE）の確認を記録します。未解決行がある倉庫は正式取込へ渡しません。

        対象商品を確認

        確認済みの全商品を対象として確認します。候補は自動選択されていますが、正式採用は確認後に行います。

          3. 出荷履歴を確認して予測

          承認済み在庫と同じJAN・倉庫の出荷履歴だけを日次化します。出荷CSV自体がない日は欠測のまま保持します。

          予測を実行

          確認済み系列だけを既存の予測Runへ登録します。確認が必要な系列は除外理由を残し、0として扱いません。

          8. 倉庫別の日次業務サマリー

          複数倉庫の不足と賞味期限リスクを同じ画面で比較します。補充候補は14日不足の参考値であり、正式な出荷指示ではありません。

          9. 到着時点在庫から推奨出荷量を試算

          工場在庫、任意の生産予定、倉庫までの時間、安全在庫を確認して試算します。入力がない商品は0とみなさず、計算対象外理由を表示します。

          入力テンプレートZIPを保存し、4つのCSVへ確認済みの値を入力してください。

          個別入力で試算する（互換・検証用）
          配送時間（12〜36時間）

          列：JAN,現在庫（箱）。商品は日次サマリーから自動表示します。

          生産予定を加える（任意）

          列：予定ID,版,JAN,完成予定日時,数量（箱）。完成済みの予定だけを本日の出荷可能量へ加えます。

          10. 試算結果を確認

          商品・倉庫ごとの推奨を採用、数量変更、見送りとして記録します。判断は設定改善候補へ集計されますが、自動反映されません。

          11. 後日実績を取り込み、予測と判断を比較

          到着予定時点までの実需要と実出荷、欠品・期限切れ・倉庫間移動を記録します。空欄は未取得、0は確認済みゼロです。

          この試算用の実績CSVを保存し、確認できた値だけを入力してください。

          3. 確認済みデータで予測する

          必要な確認を保存してから予測します。不足しているデータは理由を表示します。

          PCの負荷を調整・検証する

          対象商品の総数は制限しません。完了した予備予測の分割結果は再実行時に再利用します。取込・正式予測の全体メモリを制限する設定ではありません。

          賞味期限条件を確認

          工場・配送条件を確認

          必要な入力を確認しています。

          工場から対象倉庫までの配送時間
          複数工場・生産予定・倉庫別条件をZIPで入力

          この日次実行用の入力テンプレートZIPを保存し、4つのCSVへ確認済みの値を入力してください。

          12. 週次結果を確認し、改善候補を判断

          同じPilot ScopeのSystem・担当者判断・後日実績を7日単位で固定集計します。候補を承認しても設定は自動変更されず、次の調査対象として記録されます。

            固定済み週次版を、正式Runで実際に選択されたBaseline・候補版へ分けます。同じ業務日・JAN・倉庫で後日実績が一致するcaseだけを版間比較します。

              13. 承認した改善候補を比較検証

              承認済み候補の根拠caseを固定し、現行値と変更案を同じ後日実績で比較します。結果は正式設定へ自動反映されません。

              過去の比較計画

                14. 正式変更案を作成し、別担当者が確認

                比較検証で作成推奨となった結果から、変更差分、対象範囲、受入基準、元に戻す条件を固定します。承認しても設定は変更されません。

                過去の正式変更案

                  15. 承認済み変更をPilotで安全に試す

                  承認済み設定を固定Workerで起動確認して候補版を発行し、事前backupを固定したPilot Scopeだけで開始検査、受入評価、必要時のrollbackを記録します。現場全体の正式設定は自動変更しません。

                  実行対応済みの設定だけを人工データでsmoke testし、設定・資源上限・rollback先を改変検知可能なmanifestへ固定します。
