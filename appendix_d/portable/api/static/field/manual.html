インストール済みバージョンを確認する

現場画面の設定欄とIT担当者用の管理画面に、実際に起動しているアプリのバージョンが表示されます。不具合を伝えるときは、この番号も添えてください。フォルダー名だけで判断しないでください。

準備

起動する

  1. 配布ZIPを右クリックし、すべて展開します。ZIP内から直接起動しません。
  2. 展開したフォルダーのブンセン予測を起動.cmdを開きます。
  3. 小さい起動画面とブラウザーが開きます。初回の用途は現場担当者なら「現場利用」です。

現場向け画面のURL末尾は /field。詳細画面が表示された場合は、同じアドレスの末尾を /field にしてください。

各PCのデータは独立しています。既存の Data フォルダーを削除しないでください。

1

データを投入する

A. フォルダーに置く

  1. 投入フォルダから読み込むを開きます。
  2. 「投入ファイルを確認」の横の投入フォルダを開くを押します。
  3. 開いた Data\Incoming の白い場所へ、在庫・出荷CSVまたはZIPをコピーします。
  4. コピー完了後にしばらく待ち、投入ファイルを確認を押します。
Data
└ Incoming  ← CSV・ZIPをここへ置く
   ├ Processed  ← この中には入れない
   ├ Receipts   ← この中には入れない
   └ Rejected   ← この中には入れない

ファイル名をそろえる必要はありません。CSVは在庫・出荷分をまとめて入れます。ZIPは解凍せずに置けます。形式が不明なファイルは、列対応などの確認が必要になります。

B. 画面から選ぶ

ファイルを選ぶ（ZIP）で業務データのZIPを選び、このファイルを分析するを押します。この方法ではIncomingへコピーする必要はありません。

アプリの配布ZIPを分析画面へ投入しないでください。PDF・写真・手書きは下の専用手順を使います。

2

分析内容を確認する

  1. 処理が終わるまで待ちます。確認が必要な商品や項目を開きます。
  2. JAN、倉庫、基準日時、数量の単位などを確認します。箱・くくり・パレットの換算は現場の実際の数量に合わせます。
  3. 不足情報を補足し、確認した内容を保存します。不明な値を推測で埋めません。
  4. 予測対象と条件を確認し、画面の予測開始ボタンを押します。

出荷ゼロと欠測は異なります。不明な商品の扱いは画面の確認・除外案内に従ってください。

3・4

結果を確認し、判断を保存する

  1. 商品名・JAN・倉庫で必要な結果を探します。対象期間と数量単位も確認します。
  2. 元の予測量を確認し、採用・数量変更・保留のいずれかを選びます。
  3. 変更・保留は理由を記入し、保存します。元の予測は残ります。
  4. 全件または必要な商品の選択ダウンロードを利用します。

予測は判断の参考情報です。未確認・予測不可の表示も確認してください。困ったことや改善意見は使い方・困ったことを伝えるから記録できます。

手書き・写真・PDFを読み取る

最初の1回：APIキーを保存

  1. 開始画面上部のAI・API設定を押します。
  2. OpenAI APIキーを入力し、このPCに保存・変更を押します。
  3. 「APIキーをこのPCに保存しました」のダイアログでOKを押し、「保存済み」を確認して閉じます。キーは暗号化保存され、再表示しません。

保存は接続成功を意味しません。API利用料金が発生します。ログ送信用Tokenとは別です。

読み取りと確認

  1. 手書き・写真・PDFから取り込むを開きます。
  2. PDF・PNG・JPEG（1ファイル10MBまで）を選び、原本を登録するを押します。
  3. 原本全体をOpenAIへ送る説明を確認し、同意してAIで読み取るを押します。
  4. 原本と抽出結果を照合し、JAN・数量・日付・単位などを修正します。不明な行は理由を付けて除外します。
  5. 全行確認を保存して確認済みデータを分析へ渡すへ進みます。

AIの読み取りは間違えることがあります。確認前の抽出結果を、そのまま正式データとして扱わないでください。

PDFの読取結果を確認する（pilot.24）

  1. 印刷在庫表は印刷在庫表を読み取る（API不要）を選べます。対応形式以外と手書きは、送信に同意してAI読取を使います。
  2. 複数ページは未読取ページを続けて読み取るで順番に保存します。途中で失敗しても成功したページは残ります。
  3. JANマスターはXLSXのシートと適用開始日を指定して登録します。対象日に適した版を選び、候補を原本と照合します。同じJANでも別の商品コードは区別します。
  4. 現在ケース数・現在バラ数を別々に確認します。空欄は未確認です。原本上でゼロを意味すると確認できた場合だけ0を入力してください。C入の値は換算候補であり、箱への換算を確認する必要があります。
  5. 読取後は確認一覧が開きます。左端の不足・形式エラーの理由、赤枠の入力欄を確認してください。商品名・JAN・倉庫の検索と「不足・形式エラーのみ」の絞り込みができます。数量・日付・単位を一覧で修正し、足りない明細は手入力で追加できます。入力OKでも原本との照合は必要です。不明な行は理由を付けて除外します。全体が読めていない場合は、未読取部分の保留と採用範囲を記録します。
  6. 原本確認を保存し、確認済みデータを分析へ渡すを押します。全体の確認完了と部分採用は区別して保存します。

再読取は指定ページを再読取する（追加料金）から行います。確認保存後の原本・判断は変更できません。再読取時は画面が更新されるので、修正中の内容に注意してください。

キー保存成功とAPI認証成功は別です。認証エラー時は有効なキーをAI・API設定で保存し直してください。手書きのJAN・年・単位を自動確定しません。

本日の作業を完了する

判断を保存した後、確認完了画面の本日の作業を完了を押します。設定済みの場合はログ送信を試みます。送信できない場合も業務は完了できます。

開始画面上部のログ提出・アップデートで未送信件数や要確認件数を確認できます。終了は小さい起動画面から行います。ブラウザーだけ閉じてもアプリは終了しません。

IT担当者：ログ送信の初期設定
  1. アプリ起動後、同梱の Feedback接続設定_管理者.cmd を開きます。
  2. 管理者確認後、そのPC専用の端末設定JSONを登録します。
  3. 端末IDを選び、送信先・鍵の指紋・送信同意を確認します。
  4. この端末で接続するを押し、接続成功を確認します。

設定JSONはTokenを含むためIT担当者が管理し、共通ZIPに追加しません。受信秘密鍵は現場PCに置きません。接続テストの成功と通常業務ログの受付は別の確認です。

更新する

  1. 作業を保存し、開始画面上部のログ提出・アップデートを開きます。
  2. 更新を確認を押します。
  3. 新しい公開版がある場合に「アップデートする」が表示されます。再起動の確認後に実行します。

更新中は電源を切らないでください。新しいZIPを別フォルダーへ展開しただけでは、以前のDataや認証設定は移りません。手動入替はIT担当者へ依頼してください。

API設定は、詳細画面と4ステップ画面のどちらも画面上部の「AI・API設定」から開けます。

PDF・画像は「PDF・手書き・写真を取り込む」または「手書き・写真・PDFから取り込む」から登録します。Incomingに置いた場合は「投入フォルダの画像・PDFを確認」を押します。APIキーは画面上部に保存状態が表示されます。

保存できたことを確認する

APIキー、CSVの列対応、PDFの確認内容、JANマスター、担当者の判断、改善意見、ログ送信設定を保存すると、完了ダイアログが表示されます。内容を確認して「OK」を押してください。保存の確認ができない場合は画面の案内を確認し、入力内容を残したまま再試行してください。

APIキーの保存はAPI接続成功を意味しません。ログ送信設定の保存もサーバーへの送信完了とは別です。

困ったとき

フォルダーが開かない
小さい起動画面の「投入フォルダを開く」も試してください。開く先はアプリが動いているPCです。
ファイルを入れても進まない
Incoming直下か、コピーが完了したかを確認し、「投入ファイルを確認」を押します。確認待ち項目やエラーも確認してください。
APIキーを保存できない／読み取れない
現場で使うWindowsユーザーで設定します。キー・ネット接続・API利用条件をIT担当者に確認してください。
アップデートの実行ボタンがない
新しい公開版が見つかったときに表示されます。「ブンセン予測を起動.cmd」から起動してください。
管理者にブロックされた
エラー画面・発生時刻・版番号をIT担当者へ伝えてください。セキュリティ機能を無効にしないでください。

問い合わせ時にTokenやAPIキーの文字列は送らないでください。

印刷する場合はブラウザーの印刷機能（Ctrl + P）を使います。／ ブンセン予測 操作マニュアル
